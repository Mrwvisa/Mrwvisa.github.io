MoVieS：一秒重建动态 4D 场景的「会动的高斯像素」

MoVieS: Motion-Aware 4D Dynamic View Synthesis in One Second · arXiv 2507.10065 · github.com/chenguolin/MoVieS · 8 数据集 · CVPR 2026

§0速览卡

核心解读

前面的 L4GM 解决「物体级、静态相机」的 4D；MoVieS 把目标换成场景级、单目、带相机运动的视频：动态世界里的 3D 场景。它的表示叫「dynamic splatter pixel」——每个输入像素对应一个高斯 {x, a}（位置 + 姿态/大小/透明度/颜色共 11 维），再给每个高斯挂一条随时间变化的变形场 m(t) = {Δx(t), Δa(t)}：时刻 t 的高斯就是 x+Δx(t)、a+Δa(t)。这个表示把「外观、几何、运动」三件事统一在一组参数里，而且每个高斯天然可追踪——把高斯沿时间推过去，就是 3D 点追踪。网络结构是把 VGGT 当基座：DINOv2 编码每帧、VGGT 的注意力块做帧间交互，再挂三个 DPT 头——深度头（VGGT 初始化）、splatter 头（从零训，带 RGB 捷径）、运动头（时间条件 AdaLN）。整段 posed 视频一次前馈出 4D 高斯，单场景 0.93 秒；渲染新视角、3D 跟踪、场景流、动体分割全从这一个模型里长出来。整套方法概括起来就是：把动态场景表示成「会动的 splatter pixel」——每个输入像素一个高斯加一条随时间变化的变形场，一次前馈同时输出外观、几何与运动；渲染、跟踪、场景流、动体分割全从这一个模型里长出来，单场景 0.93 秒。

  • 目标：输入一段已标定的单目视频（每帧带相机位姿 P∈SE(3)、内参 K、时间戳 t∈[0,1]——未标定的情况论文留给未来工作），一次前馈输出每个输入像素的动态 splatter pixel：规范空间位置 x∈R³ + 属性 a∈R¹¹（四元数 4 + 尺度 3 + 透明度 1 + RGB 3），外加任意查询时刻 t_q 的变形量 {Δx(t_q), Δa(t_q)}。三件事一起出：新视角渲染（3DGS 光栅化）、3D 点追踪（把高斯推到 t_q）、深度。单场景 0.93 秒（结构见图 0-1）。
    图 0-1 · MoVieS 核心机制：posed 视频 → DINOv2 + 相机/时间 token → VGGT 注意力主干 → 三个头分别出深度、高斯属性、时间条件变形；合起来就是可渲染、可追踪的动态 splatter pixel。
  • 训练：
    • 输入：posed 视频片段：每帧图像 + 位姿 + 内参 + 时间戳；输入帧数可变（默认 5、最少 2），再随机采若干个「查询时刻 t_q」当输出时间戳。分辨率与宽高比也随机（动态 dataloader 支持不同 aspect ratio）。
    • 输出：三路：每帧深度 D̂；每个输入像素的 splatter pixel（规范空间位置 x、属性 a）；每个 (像素, t_q) 的变形量 Δx(t_q)、Δa(t_q)。
    • GT（按数据集各取所需）：8 个来源——静态：RealEstate10K（70K 场景，只有视频）、TartanAir（0.4K，有深度）、MatrixCity（4.5K，有深度）；动态：Spring（0.03K，深度）、VKITTI2（0.1K，深度）、PointOdyssey（0.1K，深度+跟踪）、DynamicReplica（0.5K，深度+跟踪）、Stereo4D（98K，真实，深度+跟踪）。渲染损失所有数据集都给；深度损失只在有深度 GT 的数据集算；运动损失只在有跟踪 GT 的数据集算——「异构数据集 + 各取所需」是这套训练能规模化（170 万级场景）的原因。
    • Loss：三项加权和：
      L = 1.0·Ldepth + 1.0·Lrendering + 10·Lmotion
      逐项含义（公式与符号见 §3；代码里与论文一致）：
      Ldepth = Σᵢ ‖Dᵢ − D̂ᵢ‖₂ + ‖∇Dᵢ − ∇D̂ᵢ‖₁——逐帧深度 MSE + 空间梯度 L1（代码多尺度梯度，4 个尺度）；
      Lrendering = Σᵥ ‖Iᵥ − Îᵥ‖₂ + 0.5·LPIPS(Iᵥ, Îᵥ)——M 个随机相机视角下、对应目标时刻的渲染图与真值帧（视频本身）；
      Lmotion = (1/P)Σi∈Ω‖Δx̂ᵢ − Δxᵢ‖₁ + (1/P²)Σ(i,j)∈Ω×Ω10·‖Δx̂ᵢ·Δx̂ⱼᵀ − Δxᵢ·Δxⱼᵀ‖₁——点级 L1（标签 1）+ 分布损失（标签 10）：后者约束「预测的运动向量两两点积」和真值一致，保住每帧内部点与点的相对距离结构；Ω 是有跟踪标注的 P 个可见点。
    训练课程分三段（代码/论文一致）：① 静态场景预训练 → ② 动态场景、变化视图数 → ③ 高分辨率微调。优化器：AdamW，lr 4e-4（预训练 VGGT 部分 ×0.1，新增模块全量），betas (0.9,0.95)，weight decay 0.05；cosine + 1000 步 warmup；batch 8/GPU；EMA 0.9999；bf16 + DeepSpeed + 梯度检查点；32 张 H20 约 5 天。新增模块（splatter 头、motion-splat 头、相机/时间嵌入）零初始化，保证起步不破坏预训练权重。
    图 0-2 · 训练流程：异构数据集按各自标注取损失 → 三阶段课程 → 32×H20 约 5 天。渲染是全局代理任务，把静态视频、深度、稀疏跟踪三类监督拧成一个目标。
  • 推理：
    • 输入：一段 posed 单目视频——帧数可变（最少 2 帧；评测里 DyCheck 用 13 帧、NVIDIA 用 12 帧），每帧要有位姿和内参。不需要任何逐场景优化。
    • 输出：每个输入像素的 dynamic splatter pixel（规范空间 x + 属性 a + 变形场 m(t)）。三块读法：
      • 新视角渲染：给定任意相机位姿和任意查询时刻 t_q，把 splatter pixel 推到 t_q、用 3DGS 光栅化——一张图里同时换相机和换时间（图 0-3 上）。
      • 3D 点追踪：同一个 splatter pixel 在不同 t_q 的位置就是它的 3D 轨迹；模型天然给每个像素一条轨迹，不需要额外的跟踪头（图 0-3 中）。
      • 零样本应用：把世界系的运动向量变换到目标相机坐标系 = 场景流；对运动向量的模长做阈值 = 动体分割——都没有专门训练（图 0-3 下）。
    • 后处理：没有。前馈出表示 → 渲染/追踪都是一次性计算；0.93 秒/场景（对比 MoSca 45 分钟、Shape-of-Motion 10 分钟、Splatter-a-Video 37 分钟）。
    图 0-3 · 推理流程：posed 视频一次前馈出动态 splatter pixels；渲染、追踪、场景流、动体分割都是这套表示的「读法」，不是额外模型。
  • 效果：
    • 定量（新视角）：静态 RE10K：26.98 / 81.75 / 0.111（PSNR/SSIM/LPIPS，SSIM/LPIPS 全场最优；只训静态的变体 27.60 拿 PSNR 第一）；动态 DyCheck：18.46 / 58.87 / 0.3094 三项全 SOTA（MoSca 18.24 / 55.14 / 0.3698）；NVIDIA：19.16 / 51.41 / 0.3152（仅次于 MoSca 的 21.45，但快 45min→0.93s）。
    • 定量（3D 跟踪，TAPVid-3D）：Aria Digital Twin EPE₃D 0.2153（SpatialTracker 0.5413、CoTracker3 0.5614，误差小一半以上）；DriveTrack 0.0472；Panoptic Studio 0.0352 / δ0.05 87.88%。
    • 定性：动态场景的渲染比优化类方法更平滑、伪影更少（MoSca 在稀疏输入 + 新视角/新时刻下容易过拟合到见过的视角，出现尖刺和过饱和）；零样本场景流边缘锐利、动体分割干净（图见论文）。
  • 结论：把「动态场景」表示成「每个像素一个高斯 + 一条随时间变化的变形场」，就能用一个前馈模型同时拿下外观、几何、运动三件事：渲染当代理任务把稀疏的跟踪标注放大成稠密运动理解，3D 跟踪、场景流、动体分割都成了同一套表示的免费副产品——4D 感知从「每任务一个模型」走向「一个模型多个读法」，而且快两个数量级。

QA 档案

Q：「dynamic splatter pixel」和普通 3DGS / 4DGS 表示有什么本质区别？
A：普通 3DGS 是「逐场景优化出来的一团高斯」；4DGS 通常给每个高斯挂一条轨迹或一个形变网络。MoVieS 的 splatter pixel 有三个关键差别：① 来源：每个输入像素一个高斯，位置由该像素的深度决定——和 pixelSplat/MVSplat 的像素对齐高斯同源，不是自由浮动的点；② 运动：每个高斯额外挂一个时间条件变形场 m(t)={Δx(t),Δa(t)}，t 时刻的高斯就是 x+Δx(t)、a+Δa(t)——「规范空间 + 形变」的经典分解，但这里形变由网络直接回归，不是优化出来的；③ 监督：外观/几何/运动三套监督来自不同数据集，渲染是共同代理任务。结果就是一个前馈模型同时具备「渲染」和「逐像素 3D 追踪」两种读法——普通 4DGS 优化方法不具备后者。
Q：三个头为什么这样分工？深度头为什么要从 VGGT 初始化、splatter 头为什么要从零训？
A：目的就是把「几何」和「外观」解耦。深度头负责给 splatter pixel 提供空间基准（中心 = 像素射线 × 深度），几何先验正是 VGGT 最擅长的——所以它的权重直接从 VGGT 的 depth_head 初始化（代码 load_state_dict(vggt.depth_head.state_dict(), strict=False)）。splatter 头负责颜色/透明度/尺度/旋转，这些是「渲染属性」，与 VGGT 的几何先验关系不大，从零训练更好（代码里还给它加了从输入图像到最后一层卷积的 RGB 捷径，保住高频细节）。运动头则从 VGGT 的 point_head 初始化（点预测的参数分布相近），再挂时间条件。论文消融显示：把三者拆开（而不是像 MVSplat/pixelSplat 用一个头全预测）能更好地利用预训练先验——这是「解耦 + 分别初始化」的设计意图。
Q：运动头的「时间条件」具体怎么注入？为什么用零初始化的 AdaLN？
A：查询时刻 t_q 先做正弦编码（代码 time_dim=20：sin/cos 各 10 维），过一层线性层产生 scale 和 bias，在 DPT 的卷积特征上做自适应层归一化（x = x*(1+scale) + bias）——经典 AdaLN。关键细节：这层线性层的权重和 bias 都零初始化，所以训练开始时「时间条件」等于没加（scale=0、bias=0），模型先以纯 3D 的姿态收敛，再逐渐学会用 t_q 调制特征——避免随机初始化的时间嵌入一上来就把预训练特征打乱。同一套零初始化也用在相机 token / 时间 token 的新嵌入上（代码里这些新模块还享受全量学习率，而预训练部分用 0.1× 学习率）。
Q：运动损失为什么要有「分布损失」？单靠点级 L1 不行吗？
A：单靠点级 L1 有两个问题：① 跟踪标注是稀疏的（只有部分点有 GT），点级损失只在这些点上有效，网络可能在没标注的区域学出「乱动」；② 只对齐单点位置，不约束「同一帧内点与点的相对结构」，运动场可能整体合理但局部被揉皱。分布损失把「预测运动向量两两点积矩阵」对齐到真值——两两内积编码的是点对之间的相对方向/距离结构，等价于要求「这一帧的运动场整体形状」和真值一致。消融（Aria Digital Twin EPE₃D）：无运动监督 0.7938（且训练震荡、频繁 None 梯度）；只有点级 L1 0.2262；只有分布损失 0.2496；两者结合 0.2153——点级负责绝对位置、分布级负责整体结构，互补。
Q：相机信息是怎么进网络的？为什么两种方式都要？
A：两条路线互补：① Plücker 射线嵌入——把位姿和内参变成每像素一条射线的 6 维表示（像素对齐），降采样后加到图像特征上，告诉网络「每个像素对应的空间射线」；② 相机 token——位姿和内参过线性层变一个 token，拼进 token 序列，让注意力层能直接读取相机上下文。消融（RE10K PSNR）：无相机 25.56；只有 Plücker 25.81（几乎等于没有）；只有 camera token 26.81；两者都有 27.60。结论：相机 token 提供全局的相机感知（关键），Plücker 提供像素级的几何对齐（补充）——一个从「序列」层面、一个从「特征」层面注入。
Q：既然主干从 VGGT 初始化，那这项工作是「站在 VGGT 肩膀上」还是「没有 VGGT 也行」？
A：论文的消融说得很直白：VGGT 初始化不是必需组件，只是加速收敛。224×224 分辨率、DyCheck 上：VGGT 初始化的版本 2 天到 17.97 dB mPSNR；从零训练的版本 6 天到 16.64 dB 且还没收敛——约 3 倍训练成本差距。这也意味着 MoVieS 的方法论（动态 splatter pixel + 三头 + 多数据集监督）与具体主干解耦；但工程上，VGGT 预训练提供的几何先验对「训练稳定性」（论文特别强调训练不稳）显然是实打实的帮助。
Q：为什么必须要「posed」视频？没位姿怎么办？
A：这是方法边界：输入需要每帧的相机位姿与内参，论文明确把「unposed videos」留给未来工作。原因是三维表示（规范空间、世界系运动）都以相机位姿为锚——没有位姿，splatter pixel 的「规范空间」和跨帧运动都无从定义。工程上可以前置一个位姿估计器：论文在 DAVIS 野外视频上就是用 MegaSaM 估的位姿（仓库也提供了这批预处理视频与位姿）。这和本站「前馈几何基座」路线（DUSt3R/VGGT 直接出位姿）正好可以串联：VGGT 出位姿 → MoVieS 出 4D。
Q：论文和发布代码有哪些值得注意的出入？
A：① 颜色表示：论文的属性 a 写的是 RGB（3 维），代码默认 sh_degree=0——即只有球谐的 DC 项（等价 RGB），没有视角相关的 SH 高阶项；② 深度损失：论文公式写 MSE + 梯度 L1，代码的梯度项是多尺度（4 个尺度）；③ 置信度：代码有 depth_conf_alpha / motion_conf_alpha，但默认 0——即没有启用置信度加权，和论文「omitted confidence-aware weighting」一致；④ 学习率分配：代码 lr_mult=0.1 且排除 splatter/motion-splat 头和相机/时间嵌入——预训练部分 0.1×、新增模块全量，论文正文没展开；⑤ 额外头：代码里还有一个 motion_splat_head（以静态高斯属性为 shortcut 预测运动后的属性），论文的「Motion w/o NVS」消融对应的实现；⑥ 帧数：训练默认 num_input_frames=5、最少 2；评测时 DyCheck 用 13 帧、NVIDIA 用 12 帧。
Q：它的局限和适用边界？
A：① 必须 posed（见上）；② 动态数据集上 NVIDIA 的 PSNR 输给 MoSca（19.16 vs 21.45）——MoSca 用静态多视图优化 + 长视频拟合，在「相机抖动大、动态复杂」的场景里仍有优势，MoVieS 赢在泛化与速度；③ RE10K 静态集上「完整动态模型」的 PSNR 略低于「只训静态」的变体（26.98 vs 27.60）——加运动建模对纯静态数据有一点点让步；④ 依赖训练数据标注质量（深度/跟踪 GT 的噪声会进模型）；⑤ 长视频、大场景、极端动态没有专门验证；⑥ 不可编辑（运动由网络输出，不能交互改动作）。

§1Motivation

问题是什么、难在哪、别人怎么解、MoVieS 怎么解。

真实世界是动态的，但 3D 视觉的大多数模型还是「静态 + 分任务」：单目深度一个模型、新视角合成一个模型、点追踪又一个模型；做 4D 场景重建要么需要多机位视频、要么每个场景优化几十分钟。MoVieS 的问题很直接：能不能用一个前馈模型，从一段普通单目视频里同时产出外观、几何和运动？它的答案是把三件事压进同一个表示：每个输入像素一个高斯（外观 + 几何），每个高斯挂一条随时间变化的变形场（运动）；三个 DPT 头分别预测深度、高斯属性、时间条件变形。渲染是共同代理任务，把静态视频、深度标注、稀疏跟踪标注三类数据拧成一个训练目标——渲染和新视角合成提供稠密监督，跟踪标注负责把「运动」钉在物理上。整套方法概括起来就是：把动态场景表示成「会动的 splatter pixel」——每个输入像素一个高斯加一条随时间变化的变形场，一次前馈同时输出外观、几何与运动；渲染、跟踪、场景流、动体分割全从这一个模型里长出来，单场景 0.93 秒。

1.1面临的问题和难点

4D 感知任务各自为战

深度、新视角合成、3D 追踪、场景流、动体分割——每个任务都有自己的模型和数据管线，几何先验无法共享；同一段视频被不同模型解读出不一致的 3D 结构。

要统一，就得有一个能同时承载「外观、几何、运动」的表示，而且这个表示必须可微、可渲染、可追踪。

动态 4D 的两条老路都有硬伤

优化类（MoSca / Shape-of-Motion / Splatter-a-Video）逐场景拟合，质量可以很高，但要 10~45 分钟/场景，依赖视频分割 mask，稀疏输入下容易过拟合到见过的视角。

前馈类此前只解决静态（pixelSplat/MVSplat/DepthSplat）或物体级 4D（L4GM）——场景级、动态、单目、带相机运动的前馈 4D 还是空白。

1.2别人是怎么解决的

路线代表工作做法 & 痛点
优化式动态 4D MoSca / Shape-of-Motion / Splatter-a-Video 逐场景优化形变场/高斯轨迹。质量高但要 10~45 分钟，需视频分割 mask 辅助，稀疏输入易过拟合视角。
前馈静态 3DGS pixelSplat / MVSplat / DepthSplat 稀疏视图一次前馈出高斯，快且泛化好；但假设场景静态，动态物体会被硬拟合成静态几何。
前馈物体级 4D L4GM 单目视频一次前馈出「会动的物体」；只做抠图后的单物体、静态相机，不是场景级。
点追踪 CoTracker3 / BootsTAP / SpatialTracker 2D 跟踪很成熟；3D 版本依赖单目深度估计反投影，深度噪声直接进 3D 轨迹（EPE 被放大）。

1.3MoVieS 是怎么解决的

核心思想：用一个「可渲染 + 可变形 + 逐像素」的统一表示，把外观、几何、运动变成同一个模型的三种输出；再用渲染当代理任务，把三类异构监督拧到一起。四个决定：

  • 动态 splatter pixel：每个输入像素一个高斯（位置 x + 属性 a），每个高斯挂时间条件变形场 m(t)。渲染 = 推到 t 后光栅化；追踪 = 同一高斯在不同 t 的位置；场景流 = 运动向量换系。表示一次定义，五个任务共享。
  • 三个解耦的头：深度头（VGGT 初始化，负责几何基准）、splatter 头（从零训 + RGB 捷径，负责外观）、运动头（AdaLN 注入查询时刻，负责动态）。各取所长的初始化，而不是一个头全包。
  • 渲染当代理任务：任何有视频的数据集都能提供渲染监督；有深度/跟踪 GT 的数据集再额外加对应损失。170 万级场景的异构数据因此可以一起训——这是「前馈 4D」能规模化的关键。
  • VGGT 当主干：几何预训练的注意力块 + DINOv2 特征，全量微调；相机用「Plücker + camera token」双路注入，时间用时间戳 token。预训练让训练稳定、收敛快（消融：从零训要 3× 时间）。

1.4优点和效果

  • 一个模型五项能力：新视角合成、深度、3D 点追踪、场景流、动体分割——后两者零样本，不需要任务专用训练。
  • 场景级动态 4D 前馈：DyCheck 18.46 / 58.87 / 0.3094 三项 SOTA（超过 MoSca 等优化方法）；TAPVid-3D 3D 跟踪 EPE 0.2153，比 SpatialTracker 低一半以上。
  • 快两个数量级：0.93 秒/场景（MoSca 45 分钟、Shape-of-Motion 10 分钟、Splatter-a-Video 37 分钟）。
  • 泛化：RE10K 静态、DyCheck/NVIDIA 动态、DAVIS 野外（位姿由 MegaSaM 估计）都能跑；说明「学的不是某个数据集，是运动与几何的关系」。
  • 工程友好：32 张 H20 训 5 天；推理无需逐场景优化，接 gsplat 渲染。

2.2动态 Splatter Pixel 表示

  • 静态部分 {x, a}：每个输入像素对应一个高斯，位置 x∈R³ 定义在共享的规范空间（首帧相机坐标系）里，其余属性 a∈R¹¹＝旋转四元数 4 + 尺度 3 + 透明度 1 + RGB 3（代码 sh_degree=0，颜色就是 DC 项的 RGB，不含视角相关球谐；论文的「RGB」与此一致）。
  • 动态部分 m(t)：每个高斯额外挂一条随查询时刻变化的变形场 m(t)={Δx(t), Δa(t)}，t 时刻的高斯为 x+Δx(t)、a+Δa(t)。Δx 是规范空间里的 3D 位移（世界系表达），Δa 是属性（尺度/旋转/透明度/颜色）的增量。
  • 为什么这个表示是「统一」的：渲染 = 选一个相机位姿 + 一个 t_q，把高斯推到 t_q 后光栅化；3D 追踪 = 同一个高斯在不同 t_q 的 x+Δx(t_q) 序列；场景流 = Δx 变换到目标相机系；动体分割 = |Δx| 阈值。五个任务读的是同一组参数，不需要给每个任务加头。
  • 规范化：和 VGGT 一样，用「所有 3D 点到原点平均距离」把场景尺度钉死；深度损失和运动损失里不再做额外归一化，也省掉了 DUST3R/VGGT 的置信度加权（代码里 depth_conf_alpha=motion_conf_alpha=0）——论文说这是为了训练更稳。
  • 静态/动态自动区分：在纯静态输入上，预测出的运动自然收敛到接近 0（<1e-3）——模型没有显式的「动/静分类器」，运动头自己学会了「没动就别动」。

2.3主干：DINOv2 + VGGT + 相机/时间 token

  • 视觉编码：每帧独立过 DINOv2 patch 嵌入（ViT-L/14，直接取自 VGGT-1B 的 aggregator.patch_embed），518×518 输入 → 37×37=1369 个 patch token（dim 1024）。
  • 相机注入（两路互补）：① Plücker 嵌入：位姿 + 内参 → 每像素 6 维射线，降采样后空间相加到特征图上（像素对齐）；② camera token：位姿 + 内参过线性层变一个 token，拼进 token 序列（序列级）。消融（RE10K PSNR）：无相机 25.56 → 只有 Plücker 25.81（几乎没用）→ 只有 camera token 26.81 → 两者都有 27.60。camera token 是主力，Plücker 提供像素级几何补充。
  • 时间注入：输入帧的时间戳 t_i∈[0,1] 做正弦编码，变成 timestamp token 拼进序列——模型因此知道帧的先后顺序；查询时刻 t_q 则由运动头的 AdaLN 注入（§2.4）。
  • VGGT 注意力主干：24 层「帧内 / 全局」交替注意力（dim 1024、16 头），从 VGGT-1B 初始化后全量微调；跨帧、跨相机、跨时间的信息都在这里交换。输出多层 token 缓存（层 4/11/17/23 的「帧内+全局」拼接，2C=2048 维）供三个头使用。
  • 新模块的处理：camera token、timestamp token、splatter 头、motion-splat 头都是新加的——零初始化（AdaLN 的 scale/bias 也是零），保证训练起步时模型行为与预训练 VGGT 一致；这些新模块用全量学习率，预训练部分用 0.1×（代码 lr_mult=0.1 + 排除名单）。

2.4三个预测头

  • 深度头（GSDPT）：从缓存 token 出逐帧深度 D̂ [H,W]；权重从 VGGT 的 depth_head 初始化——几何先验最值钱的部分直接继承。深度乘以像素射线得到 splatter pixel 的中心 x。
  • Splatter 头（GSDPT，从零训）：预测每像素的属性 a（四元数 4、尺度 3、透明度 1、颜色 3）。带一条RGB 捷径：把输入图像（3 通道）过一层卷积直接加到头的最后一层输出上，保住高频细节、提高颜色保真度（代码 shortcut_dim=3）。
  • 运动头（GSDPT + AdaLN，时间条件）：查询时刻 t_q 做正弦编码（time_dim=20）→ 线性层产生 scale/bias（零初始化）→ 在 DPT 卷积特征上做 AdaLN（x·(1+scale)+bias）→ 输出 3D 位移 Δx。代码里属性变形 Δa 由一个独立的 motion_splat_head 预测，shortcut 是静态高斯属性（11 维）——把「运动后的高斯」写成「静态高斯 + 增量」，让运动头只需要学「变化量」。
  • 三个头的共同点：都是 DPT 风格（多层 token 上采样融合 → 3×3 卷积 → 输出），输入都是 2C=2048 维的缓存 token，输出都对齐到输入分辨率——形状上一致，职责上解耦。

§3Loss

记号：D̂/D 为预测/真值深度；Î/I 为渲染/真值图像；Δx̂/Δx 为预测/真值 3D 运动；Ω 为有跟踪标注的可见点集合（共 P 个）。

3.1三项损失与逐符号解释

L = 1.0·Ldepth + 1.0·Lrendering + 10·Lmotion
论文 Eq.1。三项的量级差靠权重拉平：运动损失压得最重（10），因为它只在稀疏跟踪点上出现、信号最弱；深度和渲染各 1。下面逐项展开。
Ldepth = Σi=1N ‖ Di − D̂i ‖2 + ‖ ∇Di − ∇D̂i ‖1
逐帧深度损失：第一项是像素级 MSE，第二项是空间梯度 L1（相邻像素差分，管边缘与平面）。代码细节：梯度项是多尺度的（4 个尺度，每隔 2s 像素采样重算），且损失支持置信度加权——但默认 depth_conf_alpha=0，等价于不加权，和论文「省略 confidence-aware weighting」一致。只用在有深度 GT 的数据集（TartanAir / MatrixCity / Spring / VKITTI2 / PointOdyssey / DynamicReplica / Stereo4D）。
Lrendering = Σv=1M ‖ Iv − Îv ‖2 + 0.5 · LPIPS(Iv, Îv)
在 M 个随机采样的相机视角下，用「目标时刻」的高斯渲染图像 Îv，和对应时刻的真值帧 Iv 比：像素 MSE + 0.5×LPIPS（感知损失）。所有 8 个数据集都提供这一项——它是把「只有视频没有几何标注」的 RE10K 也拉进训练的原因，也是「渲染当代理任务」的具体落地。
Lmotion = (1/P) Σi∈Ω 1·‖Δx̂i − Δxi‖1 + (1/P²) Σ(i,j)∈Ω×Ω 10·‖ Δx̂i·Δx̂j⊤ − Δxi·Δxj⊤ ‖1
运动损失 = 点级 + 分布级：
第一项（点级，权重 1）：逐点 L1，预测位移对齐真值位移（真值 = 跟踪点在两帧间的 3D 位移）；
第二项（分布级，权重 10）：把「预测运动向量两两点积」和「真值运动向量两两点积」对齐——内积编码点对之间的相对方向与距离结构，逼运动场保持帧内几何关系（不是一帧里的点各自乱飞）；
Ω、P：有跟踪标注且可见的点集合与点数；Δx̂i·Δx̂j⊤ 是两个 3D 向量的内积（标量）。代码里分布项对最多 1000 个点随机采样算（motion_dist_sample_number=1000），控制矩阵规模。
消融（Aria Digital Twin EPE₃D）：无运动监督 0.7938（训练震荡）→ 只点级 0.2262 → 只分布 0.2496 → 两者 0.2153。

§5Conclusion

5.1这篇论文证明了什么

  • 一个表示可以同时承载三件事：dynamic splatter pixel（每像素一个高斯 + 时间条件变形场）让外观、几何、运动共享一套参数；渲染、3D 追踪、场景流、动体分割都是这套表示的「读法」，不需要为每个任务单独设计模型——4D 感知从「多模型」走向「一模型多读法」。
  • 渲染是极好的代理任务：任何有视频的数据集都能提供稠密监督，深度/跟踪 GT 只在部分数据集上补充——异构数据因此可以联合训练。这是「前馈 4D」能规模化到 170 万级场景的关键设计。
  • 场景级动态 4D 前馈可行且快：DyCheck 三项指标超过优化方法，单场景 0.93 秒（快 10~3000 倍）；NVIDIA 上虽不及 MoSca，但泛化与速度优势明显。
  • 3D 跟踪可以直接在共享世界系做：把「逐像素高斯沿时间推」当作跟踪，EPE 0.2153 远低于 2D 跟踪 + 深度反投影（0.54~0.56）——几何一致性比后处理更值钱。
  • 零样本能力来自表示：场景流/动体分割没专门训过，直接从运动向量里读出来——说明模型学到的是可迁移的运动物理量，而非任务捷径。

5.2局限（论文自述 + 读代码看出来的）

  • 必须 posed 视频：位姿与内参是表示的锚；未标定视频留给未来工作（工程上可前置 MegaSaM / VGGT 估位姿）。
  • 动态优化强项场景仍会输：NVIDIA（相机抖动大、动态复杂）MoSca 21.45 vs MoVieS 19.16——逐场景优化在「数据够、算力够」时仍有上限优势；MoVieS 赢在泛化与速度。
  • 静态纯度有一点让步：RE10K 上完整动态模型 26.98 低于只训静态的变体 27.60——运动建模会分走一点容量。
  • 依赖标注质量：深度/跟踪 GT 的噪声会进模型；异构数据集的域差靠课程和三阶段训练硬压，训练本身「特别不稳」（论文原话）。
  • 未验证的边界：长视频、超大场景、极端动态、多物体交互；运动由网络输出，不可编辑、不可交互修改。
  • 成本：32×H20 × 5 天；推理 0.93 秒虽快，但模型依赖 VGGT-1B 级别主干，显存门槛不低。

5.3后续方向（本站路线图把它们串成了一条线）

  • Unposed 4D：把 DUSt3R / VGGT 这类几何前端接在 MoVieS 前面，就能处理未标定视频——「几何基座负责位姿、MoVieS 负责 4D 表示」是自然的组合。
  • 更大规模、更长视频：动态 splatter pixel 的表示与序列长度解耦，扩展到长视频/大场景是工程问题（显存与一致性）。
  • 与占用/驾驶路线汇合：本站「前馈 4D 高斯」路线上的 DrivingRecon（环视 4D 高斯）、VG3S（VGGT 特征接高斯占用）走的是「把动态高斯接到感知/占用」的方向——和 MoVieS「从视频恢复运动」正好互补：一个从视觉重建动态，一个把动态接进语义占用。
  • 编辑与工具化：当前运动是网络输出；下一步是在表示层做可交互编辑（改轨迹、换材质、拼接场景）——4D 内容创作工具的必经之路。
  • 与物体级 L4GM 互补：L4GM 解决「抠图后的单物体」，MoVieS 解决「场景级动态」——两级表示覆盖不同粒度，也提示未来可以有「物体 + 场景」联合的 4D 世界模型。
