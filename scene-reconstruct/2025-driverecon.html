DrivingRecon：环视视频直接预测 4D Gaussians 的大重建模型

DrivingRecon: Large 4D Gaussian Reconstruction Model for Autonomous Driving · arXiv 2412.09043 · github.com/EnVision-Research/DriveRecon · Waymo NOTA-DS64 + nuScenes · NeurIPS 2025

§1Motivation

问题是什么、难在哪、别人怎么解、DrivingRecon 怎么解。

街道场景的逼真 4D 重建是自动驾驶真实仿真器的地基，但主流做法是离线的：每个场景单独跑几十分钟迭代优化，参数属于那一个 clip，换一段就要重来。这条路做离线数据资产可以，做不了规模化，更上不了车。DrivingRecon 把它换成学习问题：在 Waymo/nuScenes 上训一个前馈模型，环视视频进来，一次网络前向直接吐出整段场景的 4D Gaussians——没见过的场景也一样重建。整套方法概括起来就是：在环视视频上一次前馈直接预测 4D Gaussian 场景的通用大重建模型，免逐场景优化，并可反哺感知、跟踪与规划。除了重建和新视角合成，同一个预训练模型还能做场景编辑（删物体、加物体、挪物体）和不同相机构型的车辆适配。

1.1面临的问题和难点

逐场景优化不可扩展

3DGS/NeRF 系方法每个 clip 要优化几分钟到几十分钟，参数不可迁移——"重建"是拟合过程不是模型能力。一百万段 clip 就是一百万次从头拟合。

通用前馈方法不懂驾驶场景

pixelSplat/MVSplat 这类前馈重建为稀疏视角近距离物体设计，吃不下驾驶的大尺度、多帧时序、动态物体和天空；直接搬来动态区域塌掉（表 1 里它们 Dynamic PSNR 掉 2~3 个点）。

1.2别人是怎么解决的

路线代表工作做法 & 麻烦
逐场景优化Street Gaussians / OmniRe / NeuRAD每 clip 迭代拟合，质量高但慢、参数不可迁移、不能上车。
通用前馈重建pixelSplat / MVSplat / LGM / L4GM网络直接出 Gaussians，秒级重建；但不吃时序、不懂驾驶域的尺度与动态。
借 3D 基础模型ReconDrive（后续工作）VGGT 当骨干加驾驶头；骨干强但外挂 SAM/DINO 组件多。

1.3DrivingRecon 是怎么解决的

一个端到端网络，粗细两段式。粗段全前馈：每个时刻取 3 个环视视角（stride=10 抽帧），过一个相机条件的 UNet 骨干（内参、外参、深度都作为条件注入），得到逐像素特征；一个轻量 Adaptor 头从特征里解出每个像素的 Gaussian 参数——深度用 200 档分布加回归精修表达（0.1~400m 的驾驶级量程），位置由深度反投影加可学习偏移得到，另带 3 类静态/动态/天空分割头。细段可选：对当前 clip 再做最多 500 步的带形变场的微调，把前馈结果磨到逐场景优化的质量。训练只有图像、LiDAR 深度和 3 类分割伪标签，不需要重建真值。

1.4优点和效果

  • 真·前馈：模型里没有任何冻结的第三方组件——DINOv2 只出现在数据预处理脚本里提取特征，网络前向不经过它；这点和后续借 VGGT 外挂 SAM/DINO 的 ReconDrive 形成对照。
  • 一套表征多种用途：重建出的 4D Gaussians 直接服务新视角合成、场景编辑、车辆适配，论文还展示了对感知/跟踪/规划的预训练增益。
  • 有 scaling 曲线：训练场景数从少到多，性能持续上升——"大重建模型"的名字有数据支撑（表 4）。
  • 效果预告：Waymo NOTA-DS64 重建 PSNR 23.70（MVSplat 21.33），动态区域 21.50（领先 1.7+）；新视角合成 20.63；跨场景与 Waymo→nuScenes 域迁移同样领先，细节见 §4。

§2.2Camera-Conditioned UNet

  • 扩散式骨架，不是纯 transformer：Down/Mid/Up 三段 + 跳连（scene/unet.py），与 pixelSplat/EVolSplat 一脉的相机条件 UNet；注意力只开在最深层 Down 和第一层 Up（down_attention=(F,F,F,T)、up_attention=(T,F,F)），省算力又保跨视角通信。
  • 条件是"喂进去"不是"外挂"：内参、外参、LiDAR 深度与图像一起进网络——模型必须学会"在已知相机几何下解释像素"，这也是它能适配不同相机构型车辆的原因。
  • LiDAR 的角色是条件与监督，不是输入模态：推理时深度条件可替换为估计值，主干仍是纯视觉路径。

§2.3Gaussian Adaptor

  • 像素对齐，一像素一 Gaussian：位置不靠回归 xyz，靠"深度分布期望 + 回归残差"反投影——几何由相机模型保证，网络只学深度，这是驾驶大尺度下比直接回归 xyz 稳定的关键。
  • 深度用分布不用单值：200 档（0.1~400m）覆盖驾驶量程；分布的 softmax 期望承担粗定位，1 通道回归头承担亚档精修，两段相加成最终深度。
  • 尺度与偏移都限幅：scale 经 softplus 截断在 [gaussian_scale_min, max]，偏移限幅 ±5——前馈预测 Gaussian 最怕参数飞掉，处处夹紧是能训稳的工程底线。
  • 3 类分割头自带：静态/动态/天空的粗分割由模型自己出（监督用伪标签），渲染损失里静态/动态分别加权——动静态分解是内置能力，不依赖 SAM。

§2.4Coarse-to-Fine

  • 粗段是卖点：全前馈、跨场景泛化、免优化——表 1/2 的对比都在前馈条件下做，公平。
  • 细段是保险：对当前 clip 最多 500 步微调（train.py per_scence_num=500），加形变场 _deformation 建模时序形变，把质量磨到逐场景优化档——离线数据资产生产时用得上。
  • 评测渲染 61 视角：在 −12°~+12° 内插 61 个位姿渲染（gs_render_mul），重建与 NVS 指标分开报，静态/动态分开报——动态区域单独暴露前馈方法的短板，也是本文领先最明显的地方。

§3Loss

L = λd·CE(深度分布) + λd·L2(深度精修) + λs·CE(分割) + Lrender(RGB)
权重逐项取自 forward（GS_LRM.py）：depth_weight=2（分布 CE 与 L2 各计一次）、seg_weight=1、depth_back_weight=2；天空深度损失权重 0（关闭）、法向损失 0（关闭）；渲染损失中静态/动态分量各加权 0.1。监督不需要任何重建真值——RGB 来自渲染比对、深度来自 LiDAR、分割来自伪标签。
图 3-1 · 损失流：深度双路（分布 + 回归）、分割、渲染三项，全部可自动生成监督。
  • 深度双路监督：分布 CE（200 档分类）管全局量程，L2 管精修残差——和 Adaptor 的两段深度输出一一对应。
  • 渲染损失的静动态加权都是 0.1：直接作用在像素上的光度项反而是"辅助"角色，几何项（深度 ×2）才是主力——先几何后外观的次序符合驾驶场景的优先级。
  • NaN 防御是常态：每项损失前都有 isnan 检查丢弃——前馈出 Gaussian 的训练稳定性要靠这些补丁，Adaptor 的限幅设计同理。

§5Conclusion

5.1这篇工作证明了什么

  • 驾驶场景的 4D 重建可以从"逐 clip 拟合"变成"模型能力"：环视视频一次前馈出 Gaussians，跨场景有效。
  • 相机条件 UNet + 像素对齐 Adaptor + 限幅，是让前馈 Gaussian 在驾驶域训稳的一套够用组合。
  • 重建出来的表征能反哺感知/跟踪/规划、支撑编辑与车辆适配——重建不是终点是资产。

5.2局限

  • 骨干是 UNet 不是基础模型：预训练红利只来自本任务数据，"Large" 的天花板受训练集规模限制（表 4 曲线未饱和即是机会也是短板）。
  • 细段每 clip 500 步仍是逐场景优化——宣称"免优化"的是粗段，读论文时要分清两个口径。
  • 3 类分割粒度粗，动静态分解依赖伪标签质量；深度监督依赖 LiDAR。

5.3后续方向

  • 换更强骨干：后续 ReconDrive 用 VGGT 基础模型替换 UNet 即此路线（代价是外挂组件变多）。
  • 把前馈重建头接到检测/规划骨干上当预训练监督——本文"反哺感知"的实验已给出雏形，系统化就是一条独立研究线。
  • 更高维的编辑与仿真闭环：删改物体后的再渲染一致性、与驾驶策略的交互。
