VG3S：把前馈几何基座的先验，灌进高斯占用预测

VG3S: Visual Geometry Grounded Gaussian Splatting for Semantic Occupancy Prediction · arXiv 2603.06210 · 港科大（沈劭劼组）· IROS 2026 · 论文源包（无公开代码）

§0速览卡

核心解读

3D 语义占用预测是自动驾驶感知的核心任务：把环视图像变成一张带语义的 3D 体素网格。近年高斯路线（GaussianFormer / GaussianFormer-2）用几千到几万个语义高斯表示场景、再 splatting 成体素，省算力、可解释；但它们的图像编码器是「跟占用任务一起从零训」的——3D 监督只有稀疏的占用标签，学不出强几何先验，于是重建出来的物体结构经常是碎的（平面断裂、建筑缺角）。VG3S 的观察是：VGGT / DVGT 这类几何基座在训练时见过海量多视图 3D 数据，冻结起来就自带强跨视图几何先验——直接拿它们的 token 给占用用行不行？不行，通用 token 没有占用任务需要的空间结构和任务对齐。所以 VG3S 在冻结 VFM 和高斯解码器之间插了一个可插拔适配器 HGFA：先按层分组、用学习到的权重融合（GATF），再做任务对齐的残差精炼（TATR），最后重建成多尺度空间金字塔（LSFP）。nuScenes 上 IoU 34.41（比 GaussianFormer-2 的 30.56 相对涨 12.6%）、mIoU 21.52（相对涨 7.5%）；换成 DINOv2 / VGGT / DGGT / DINOv3 / DVGT 五种底座都涨——它是本站路线图上「前馈几何基座 × 前馈 4D 高斯」的汇合点：几何基座提供先验，高斯表示负责占用。整套方法概括起来就是：冻结一个几何基座视觉大模型（VGGT/DVGT 等），用一个可插拔的层次几何特征适配器把它的通用 token 变成占用专用特征，再喂给高斯解码器——高斯占用预测因此拿到了跨视图几何先验，nuScenes IoU 34.41（+12.6%）、mIoU 21.52（+7.5%）。

  • 目标：输入 6 路环视图像（nuScenes，360°），输出 200×200×16 的语义占用体素网格（100m×100m×8m 范围、0.5m 体素）。场景用 J=25,600 个语义高斯表示（位置 + 协方差 + 不透明度 + 语义 logits），经 Gaussian-to-voxel splatting 变成体素；核心创新不在解码器，而在「怎么把冻结几何基座的特征适配给解码器」——一个可插拔的 HGFA 适配器（结构见图 0-1）。
    图 0-1 · VG3S 核心机制：冻结几何基座 VFM 出多层 token → HGFA 三模块适配成占用专用特征 → 高斯解码器 → Gaussian-to-voxel splatting 出语义占用。shape 取自论文实现细节（K=4、M=6、J=25,600、D=128、体素 200×200×16）。
  • 训练：
    • 输入：nuScenes 6 路环视图像（[6,3,H,W]，360°），不做任何位姿/深度输入；VFM 全程冻结（权重不动），只训练 HGFA 适配器和高斯解码器。
    • 输出：25,600 个语义高斯（位置、协方差、不透明度、16 类语义 logits）→ Gaussian-to-voxel splatting → 200×200×16 的语义占用网格（每类一个概率，叠加成最终占用）。
    • GT：SurroundOcc 提供的稠密语义占用标签（nuScenes 场景，2Hz 标注）；范围 100m×100m×8m、体素 0.5m。17 类（16 个语义类 + 空）。
    • Loss：交叉熵 + Lovász-Softmax 两项加权：
      Ltotal = λ · LCE + β · LLovász
      符号：LCE 是逐体素/逐类的交叉熵（标准语义分割损失）；LLovász 是 Lovász-Softmax 损失（对 IoU 的直接可微近似，专门优化分割的 IoU 指标，缓解类别不平衡）；λ、β 是平衡系数——论文没有给出具体数值，只说与既有占用工作一致（GaussianFormer / TPVFormer 的常用设置）。复现时这是需要自己调的一处。
    实现细节（论文 §4.1.3）：HGFA 分 K=4 组、每组 M=6 层；TATR 的组扩展比 ρ = {4, 3, 2, 1.5}（浅层大、深层小）；LSFP 的扩展隐维 DH = {768, 512, 384, 256}、空间尺度 τ = {4, 2, 1, 0.5}；解码器 4 个 transformer 块、J=25,600 个高斯、通道 D=128；cosine 学习率 + 500 次迭代线性 warmup、峰值 2e-4；数据增强为图像缩放 + 光度扰动。论文未说明训练硬件与时长（源包中无此信息）。
    图 0-2 · 训练流程：冻结 VFM 出 token → 只训练 HGFA 与高斯解码器 → 体素化后算 CE + Lovász。VFM 不参与梯度更新，这是「省算力 + 防遗忘」的关键。
  • 推理：
    • 输入：6 路环视图像（nuScenes 相机配置），一次前馈；不需要深度图或额外的几何输入，也不需要逐场景优化。VFM 直接吃图像出 token；解码器沿用 GaussianFormer-2 的 view-guided deformable attention 采样多视图特征（相机标定沿用 nuScenes 设定）。
    • 输出：200×200×16 的语义占用网格（16 语义类 + 空），可进一步导出检测/规划用的占用查询。单模型一次前向；具体推理时延论文未报告（只报告了精度与训练配置）。
    • 可插拔性：换 VFM 不用改解码器——论文把 DINOv2 / VGGT / DGGT / DINOv3 / DVGT 五种底座分别插进同一个 HGFA + 解码器，全部稳定超过基线（见 §4.2）。这也是「适配器」设计的核心价值：VFM 在演进，占用框架不用重训。
    • 后处理：无。Gaussian-to-voxel splatting 直接出体素，不需要额外优化或融合。
    图 0-3 · 推理流程：6 路图像 → 冻结 VFM + HGFA → 高斯解码 → 体素占用。VFM 可替换，适配器与解码器保持不变。
  • 效果：
    • 定量：nuScenes 验证集：IoU 34.41（基线 GaussianFormer-2 30.56，相对 +12.6%）、mIoU 21.52（基线 20.02，相对 +7.5%），同时超过体素路线代表 SurroundOcc（31.49 / 20.30）与 OccFormer（31.39 / 19.03）。16 个语义类里 12 类最优——driveable surface 42.42、manmade 17.46、vegetation 25.76、terrain 26.58 等结构性类别提升最明显；car / pedestrian / traffic cone 仍低于部分强基线（见 §4.1 的诚实标注）。
    • 可替换性：同一套 HGFA + 解码器，换 DINOv2 → IoU 32.34 / mIoU 20.42；VGGT → 33.29 / 21.10；DGGT → 33.37 / 20.81；DINOv3 → 33.20 / 21.36；DVGT → 34.41 / 21.52。全部超过基线 30.56 / 20.02——「几何先验」而不是「更强的图像底座」是主要增益来源（DINOv2 vs VGGT 的对比说明了这一点）。
    • 定性：对比 GaussianFormer-2，VG3S 的路面更连续（不再断裂）、建筑/人造结构更完整，交叉路口场景的上层建筑和下层结构都能补全（论文图 3）。
  • 结论：把几何基座「冻结 + 适配」而不是「全量微调」，就能把跨视图几何先验注入高斯占用：一个轻量 HGFA 适配器让 25,600 个高斯的重建结构从碎片化变成连续完整，IoU +12.6%、mIoU +7.5%，且换任何几何 VFM 都成立——路线一（几何基座）与路线三（高斯）由此汇合。

QA 档案

Q：为什么要把 VFM 冻结，而不是像常规做法那样微调？
A：三个理由。① 算力：VGGT/DVGT 这类基座是 10 亿参数级，全量微调对占用这种下游任务太贵；冻结后只训 HGFA 和解码器，训练成本降一个量级。② 防遗忘：论文明确指出全量微调有「灾难性遗忘」风险——基座里宝贵的通用 3D 几何先验会被占用数据的小分布覆盖掉。③ 可插拔：冻结意味着 VFM 是一个标准接口，换底座（DINOv2→VGGT→DVGT）不用改解码器，VFM 升级直接受益。并发工作 VG3T 就是全量微调 VGGT 做占用——论文把它作为对照，说明「不微调也能拿到几何先验，而且更省」。代价是：VFM 的通用 token 不能直接用于占用，必须加一个适配器（HGFA）来「翻译」——这正是本文的主要贡献。
Q：直接拿冻结 VFM 的 token 喂解码器为什么不行？差距有多大？
A：VFM token 活在「通用视觉潜空间」里：它们编码的是跨视图对应、深度、结构等通用几何信息，但没有占用任务需要的空间网格结构和任务对齐（哪些 token 该强调、哪些该抑制、如何还原成 h×w 稠密特征）。消融直接量化：把整个 HGFA 换成一个标准 DPT 层，IoU 从 33.29 掉到 30.59、mIoU 从 21.10 掉到 19.31——几乎退回基线 GaussianFormer-2（30.56/20.02）的水平。也就是说：几何先验在 token 里，但需要专门的适配器才能被占用解码器用起来；没有适配器，冻结 VFM 等于白拿。
Q：HGFA 的三个模块各自解决什么问题？去掉任何一个会怎样？
A：按数据流：GATF（分组自适应 token 融合）解决「层太多、信息冗余」——把 N 层分成 K=4 组、每组用 softmax(MLP) 学出层间权重再加权求和，动态抑制冗余几何响应（去掉：IoU −0.77、mIoU −0.67）；TATR（任务对齐 token 精炼）解决「通用特征和占用任务不对齐」——一个轻量残差 FFN（GELU+dropout），并按组给不同扩展比 ρ（浅层大、深层小），把通用特征校准成任务特征（去掉：IoU −0.59、mIoU −0.72）；LSFP（潜空间特征金字塔）解决「token 是序列、没有空间结构和多尺度」——depthwise conv 恢复局部几何、SE 做通道重加权、point-wise conv + 残差、2D 位置编码、τ={4,2,1,0.5} 的多尺度重采样（去掉：IoU −0.72、mIoU −0.77）。三者是「压缩 → 对齐 → 结构化」的串联，缺一不可。
Q：GATF 为什么要分组？K 为什么取 4？
A：VFM 不同层的语义粒度不同：浅层是细粒度几何/纹理，深层是高层语义。直接全层融合会让不同粒度的特征互相稀释。做法是把 N 层（VGGT 是 24+ 层）按「语义粒度相近」切成 K 组（每组 M=N/K 层连续层），组内学权重融合，组间保留层次差异。消融：K=1（不分组）31.45/19.52；K=3 32.66/20.25；K=4 33.29/21.10；K=6 32.57/20.55——K=4 在「结构保真」和「信息压缩」之间最平衡（此时每组 6 层，正好对应浅/中/深几个语义段落）。
Q：论文说「主要增益来自几何先验而不是更强的图像 backbone」，怎么证明的？
A：看 VFM 替换表：DINOv2（纯语义自监督，无显式几何训练）32.34/20.42；VGGT（几何多任务预训练）33.29/21.10；DGGT（驾驶域几何微调）33.37/20.81；DINOv3（更强语义）33.20/21.36；DVGT（几何+驾驶域）34.41/21.52。关键对照是 DINOv2 vs VGGT/DGGT：同样走 HGFA，带几何监督的底座明显更高——说明「几何 grounding」是有效成分；而 DINOv3 靠更强语义也能拿到 21.36 mIoU，说明语义能力也有贡献，但两者结合（DVGT）才是最优。更细的结论：几何先验主要提升结构类（driveable/manmade/vegetation/terrain），语义先验主要帮小目标类别。
Q：为什么高斯表示适合占用预测？25,600 个高斯是怎么变成 200×200×16 体素的？
A：占用体素网格有 200×200×16 = 64 万个格子，其中绝大多数是空的；稠密体素方法要对所有格子预测，浪费算力。高斯表示把场景压成 J=25,600 个稀疏基元（每个带位置/协方差/不透明度/语义 logits），只把计算花在可能有东西的地方。Gaussian-to-voxel splatting 的过程：对每个体素中心，计算所有高斯对它的贡献（按马氏距离加权、乘不透明度），概率叠加得到占用概率；语义则按高斯条件类概率做归一化期望。最后取概率阈值 + argmax 得到 200×200×16 的语义占用。25,600 个高斯 vs 64 万体素 = 25 倍的压缩，且每个高斯携带完整协方差，能表达各向异性的结构（墙面、路面）。
Q：复现这篇论文有哪些坑？
A：① 没有公开代码（截至写页面时只找到 arXiv 源包）；② 损失权重 λ、β 论文没给，只说沿用既有占用工作——这是必须自己试的超参；③ 训练硬件、时长、batch size 论文都没写（源包中无此信息）；④ HGFA 的组数、扩展比、尺度因子、隐维都给了，但 token 分组的「按语义粒度」具体怎么切（连续层切分）需要按 K=4、M=6 推断；⑤ VFM 版本与权重（VGGT/DVGT/DGGT 的哪个 checkpoint、输入分辨率）论文未细化，影响可复现性；⑥ 基线 GaussianFormer-2 用了 128 通道特征做公平对比（表里标 *），复现时注意对齐参数量。整体属于「方法清晰、细节欠奉」的论文类型，复现成本不低。
Q：局限和适用边界？
A：① 语义类别不均衡：16 类里 car / pedestrian / traffic cone 仍不如 SurroundOcc / GaussianFormer-2——小目标、细长物体的语义仍是短板；② 依赖 SurroundOcc 稠密占用标签的质量（nuScenes 的占用 GT 本身是「伪标签」性质的稠密化结果）；③ VFM 推理成本：虽然冻结省了训练，但前向仍要跑 10 亿级基座，车端部署需要蒸馏/量化；④ 单帧多视图模型，没有利用时序（相邻帧的运动信息未用）；⑤ 只在 nuScenes 验证，跨数据集（Waymo、Argoverse）未测；⑥ 需要相机标定（view-guided deformable attention 与 nuScenes 相机配置绑定）。适用范围：有环视相机 + 标定的自动驾驶占用预测；把它当「几何基座的即插即用下游」的范式参照，比当「SOTA 占用模型」更有价值。

§1Motivation

问题是什么、难在哪、别人怎么解、VG3S 怎么解。

3D 语义占用预测要在 64 万个体素格子里同时回答「有没有东西」和「是什么」——稠密、嘈杂、3D 监督昂贵。高斯路线用稀疏基元省算力，但它的图像编码器是「和占用任务一起从零训」的：3D 标签只有 SurroundOcc 这种稀疏稠密化标注，编码器学不到强几何先验，于是重建出的物体结构经常断裂、缺角。与此同时，VGGT/DVGT 这类几何基座在训练时吃了海量多视图 3D 数据，中间 token 本身就编码了跨视图几何一致性——问题是这些先验怎么「借」给占用。全量微调太贵、还可能把先验忘掉；直接用原始 token 又和占用任务对不上。VG3S 的答案是：冻结基座，中间插一个可插拔的层次几何特征适配器（HGFA），把通用 token「压缩→对齐→结构化」成占用专用特征。整套方法概括起来就是：冻结一个几何基座视觉大模型（VGGT/DVGT 等），用一个可插拔的层次几何特征适配器把它的通用 token 变成占用专用特征，再喂给高斯解码器——高斯占用预测因此拿到了跨视图几何先验，nuScenes IoU 34.41（+12.6%）、mIoU 21.52（+7.5%）。

1.1面临的问题和难点

占用模型的几何瓶颈

环视图像 → 3D 体素是病态的 2D→3D lifting：没有深度真值，只能靠占用标签里隐含的几何。任务专用编码器从零训练，学到的「几何」只是勉强够分类，跨视图一致性差——表现为路面断裂、建筑缺顶、平面碎成片。

体素/BEV 方法还对空区域做稠密预测，200×200×16 的网格里大部分是空的，算力浪费严重。

几何基座「看得见、吃不着」

VGGT/DVGT 的 token 里有强几何先验，但它们是为「多视图几何任务」训练的：token 是通用潜变量，没有占用要的空间网格、没有任务对齐、层数多且冗余——直接接解码器效果甚至不如基线。

全量微调一个 10 亿参数基座：训练成本高、且会让通用先验被小数据集「覆盖」（灾难性遗忘）——这与「复用基座」的初衷相悖。

1.2别人是怎么解决的

路线代表工作做法 & 痛点
体素 / BEV 占用 OccFormer / SurroundOcc / BEVFormer / TPVFormer 把多视图特征 lift 到 3D 体素或 BEV/三平面，再稠密预测占用。成熟、精度可；但空区域也全量计算，内存与算力随网格增长，几何结构仍靠有限监督。
高斯占用 GaussianFormer / GaussianFormer-2 用稀疏语义高斯表示场景、Gaussian-to-voxel splatting 出占用，省算力、可解释；但编码器随任务从零训，几何先验弱 → 结构碎片化（本文的直接基线）。
VFM 全量微调 VG3T 把 VGGT 全量微调进占用。能拿到几何先验，但训练极贵、有灾难性遗忘风险，且换底座要重训。
冻结 + 适配（本文） VG3S 冻结几何基座，只用轻量 HGFA 适配 token。省算力、保先验、可插拔换底座；代价是适配器设计要够好（否则不如基线）。

1.3VG3S 是怎么解决的

核心思想：把几何基座当「冻结的先验引擎」，用一个可训练的轻量适配器把它的多层 token 翻译成占用专用特征。三个决定：

  • 冻结 VFM，只训适配器 + 解码器：VGGT/DVGT 的权重全程不动；计算省一个量级，通用几何先验不会被占用数据覆盖，还能随时换底座（DINOv2/VGGT/DGGT/DINOv3/DVGT 都验证过）。
  • HGFA 三段式适配：GATF（分组 + 学习权重，压掉冗余层）、TATR（残差 FFN + 组特定扩展比，做任务对齐）、LSFP（depthwise conv + SE + 多尺度重采样，恢复空间结构与多尺度）。三段各管一件事，消融里缺一都掉。
  • 解码器沿用 GaussianFormer-2：view-guided deformable attention 采样 + 概率高斯叠加 + Gaussian-to-voxel splatting，J=25,600 个高斯。创新集中在「特征注入」，不是重造解码器——这正是「可插拔」的含义。

1.4优点和效果

  • 精度：nuScenes IoU 34.41 / mIoU 21.52，对基线 GaussianFormer-2 相对 +12.6% / +7.5%，超过体素 SOTA SurroundOcc（31.49 / 20.30）。
  • 结构质量：路面连续、建筑完整、交叉路口不缺口——几何先验的效果直接体现在结构类（driveable/manmade/vegetation/terrain）上。
  • 可插拔：五种 VFM 底座全部稳定超基线；换更强的几何基座，占用精度跟着涨，不用重训整个框架。
  • 成本：VFM 冻结，训练只更新小适配器与解码器；基座作为通用资产复用——这是「几何基座 + 下游任务」的范式示范。
  • 局限也明确：小目标语义（car/pedestrian/traffic cone）仍不如强基线；单帧多视图、未利用时序；依赖 SurroundOcc 标签与 nuScenes 标定。

2.2冻结 VFM 的 token 提取

  • 形式化：设 VFM 编码器为 E。对每张环视图 I_i，先切成 h×w 个 patch，编码成图像 token Timg∈RL×d（L=h·w，d 为 DINO 维度）；再拼上 1 个 camera token 和 4 个 register token，得到 T∈R(1+4+L)×d。E 的权重全程冻结。
  • 交替注意力块：T 过 N 个 AA（Alternating-Attention）块。每个块里有 |B| 个注意力层：VGGT/DGGT 是 {帧内, 全局} 两层，DVGT 是 {帧内, 全局, 时序} 三层。块内把所有注意力层的输出拼接，得到 T_j∈R(1+4+L)×DV，其中 DV=|B|·d（VGGT 就是 2d=2048 维）。
  • 只留图像 token：camera/register token 是特殊 token（用于身份与相机信息），真正有用的是后 L 个图像 token：T_j∈RL×DV。收集 N 个块得到 T={T_j}j=1..N——多层几何先验的集合，这就是 HGFA 的输入。
  • 为什么这个提取对五种 VFM 都成立：接口统一为「DINO patch token + 若干注意力层 + 多层拼接」；VGGT、DGGT、DVGT 都是这个结构（DVGT 多一层时序注意力，DV=3d），DINOv2/v3 则看成只有帧内注意力的退化情形。所以「换 VFM」在代码上只是换 E，HGFA 不用改。

2.3HGFA：三个适配模块

  • GATF（分组自适应 token 融合）：把 N 层按「语义粒度相近」切成 K=4 组，每组 M=N/K=6 个连续层：G_k = T1+(k−1)M ⊞ … ⊞ TkM ∈ RM×L×DV。对每组算层间权重 ω_k = softmax(MLP_k(G_k))（ω_k∈RM×L，每个 token 有自己的一组层权重），再加权求和、LayerNorm：T̂_k = LN(Σm ωk,m ⊙ Gk,m)。作用：不是简单平均，而是按 token 动态选择该看哪几层——抑制冗余几何响应，保留最有信息量的层。
  • TATR（任务对齐 token 精炼）：残差 FFN：T̃_k = T̂_k + ΨFFNk(T̂_k)，GELU + dropout。关键设计是组特定扩展比 ρ_k={4,3,2,1.5}：浅层组（细粒度几何）给更大扩展，深层组（高层语义）更紧凑。作用：把 VFM 的通用潜空间往占用任务上校准，同时控制算力。
  • LSFP（潜空间特征金字塔）：先把 token 恢复成 h×w 网格 F'_k，然后：① depthwise conv 抓局部空间上下文：F''=ΦDW(F')；② SE 通道重加权：F'''=σ(ΨFC(ξ(F''))) ⊙ F''（ξ 全局平均池化、σ sigmoid）；③ point-wise conv + 残差：F̂ = F' + ΦPW(F''')；④ 投影到组特定隐维 DH={768,512,384,256}，加 2D 正弦位置编码；⑤ 按尺度 τ={4,2,1,0.5} 做尺度自适应重采样；⑥ point-wise conv 统一到 D=128。最后展平拼接：F∈R(L·Στ²)×128。
  • 三段的分工一句话总结：GATF 管「哪些层有用」（跨层压缩）、TATR 管「任务要什么」（对齐）、LSFP 管「空间怎么组织」（结构 + 多尺度）。消融：去掉 GATF / TATR / LSFP 分别掉 0.77 / 0.59 / 0.72 IoU（详见 §4.3）。

2.4高斯解码与体素化

  • 高斯参数：每个高斯有位置 m∈R³（按场景范围归一化到 [-1,1]³）、协方差 Σ（尺度 s∈R³ + 旋转四元数 r∈R⁴）、不透明度 a∈[0,1]、语义 logits c∈R|C|（16 类）。J=25,600 个高斯，通道维度 D=128，解码器 4 个堆叠 transformer 块。
  • view-guided deformable attention：沿用 GaussianFormer-2 的做法——把高斯的参考点投影到多视图特征上，用可变形注意力采样特征来更新高斯参数（相机标定沿用 nuScenes 设定）。这一步是「特征 → 高斯」的桥。
  • 概率高斯叠加：体素 v 的占用概率 = 1 − Πi∈J(1 − ai·exp(−½(v−mi)⊤Σi−1(v−mi))) 一类的高斯贡献聚合（GaussianFormer-2 的概率叠加框架）；语义则按各高斯的类概率加权期望归一化。最终 dense 语义占用 = 占用概率 + 逐类 argmax/期望。
  • 为什么用高斯而不是稠密体素：体素网格 64 万格、绝大部分为空；25,600 个高斯只把算力放在「有东西」的区域，且每个高斯带完整协方差，能表达各向异性的平面/墙面——结构类指标提升（driveable 42.42、terrain 26.58）正是这个表示的直接收益。

3.1损失与逐符号解释

Ltotal = λ · LCE + β · LLovász
论文 Eq.7。
LCE：逐体素多类交叉熵——把每个体素的预测分布往真值类上拉，是占用/分割的标准项；
LLovász：Lovász-Softmax 损失——对 IoU 的可微代理（先按误差排序、再对「并集误差」做 Lovász 扩展），直接优化评测指标，能缓解类别不平衡（空体素占绝大多数）；
λ、β：两项的平衡系数。论文只说「与既有占用工作一致（GaussianFormer / TPVFormer 的常用设置）」，没有给出具体数值——复现时必须自己调。
  • 没有辅助损失：没有深度损失、没有一致性正则、没有 VFM 特征对齐损失——HGFA 与解码器完全由占用标签驱动。几何先验是「已经存在于冻结 VFM」里的，不需要额外监督去教。
  • 评测指标（论文 §4.1.2）：SC IoU = TPo/(TPo+FPo+FNo)（把所有非空体素当一类，只看几何）；SSC mIoU = (1/|Co|)Σi∈Co TPi/(TPi+FPi+FNi)（逐语义类 IoU 平均）。

4.4定性结果

  • 与 GaussianFormer-2 对比四个场景：前两个场景 VG3S 的路面连续、无明显断裂（基线在远景/稀疏区域容易断）；第三个场景左侧停车场与右侧建筑结构更完整；第四个交叉路口，基线上层建筑缺失、下层结构残缺，VG3S 能补全。
  • 结构类（driveable surface、manmade、vegetation、terrain）提升最直观——几何先验主要修「形状」，语义类的提升需要更强的语义底座（如 DINOv3）配合。
  • 论文补充了可视化视频（源包外），但未报告推理时延与显存——工程落地需自行测量（VFM 前向是主要开销）。

§5Conclusion

5.1这篇论文证明了什么

  • 几何基座的先验可以「冻结借用」：不微调 VGGT/DVGT，只用一个轻量 HGFA 适配器，就能把基座的跨视图几何先验注入高斯占用——IoU +12.6%、mIoU +7.5%，同时避免了全量微调的算力与遗忘问题。
  • 适配器设计有章可循：GATF（跨层压缩）→ TATR（任务对齐）→ LSFP（空间结构化）三段各解决一个明确问题，消融里缺一都掉；「换 DPT 层」直接退回基线，证明适配器不是锦上添花，而是冻结方案成立的前提。
  • 可插拔性是真实的：五种底座全部超基线，且几何监督的底座优于纯语义底座——这说明接口设计（token + AA 块）是通用的，不是为某一个 VFM 定制。
  • 路线一 × 路线三的汇合点：几何基座（VGGT 家族）提供「结构正确的先验」，高斯表示提供「稀疏高效的可渲染/可体素化载体」——两者通过一个适配器对接，就是本站路线图上「前馈几何基座 × 前馈 4D 高斯」的接口原型。
  • 范式价值大于单点 SOTA：「冻结基座 + 下游适配器」让占用框架可以跟着基座一起升级（VGGT → DVGT → 未来 VGGT-Omega），这是比某个数据集上的 2 个点更重要的工程结论。

5.2局限（论文自述 + 读者需要知道的）

  • 语义短板：16 类里 12 类最优，但 car / pedestrian / traffic cone 仍不如 SurroundOcc——几何先验修结构，修不了小目标的语义判别；需要更强的语义底座（DINOv3）或类别重加权来补。
  • 没有时序：单帧多视图模型，相邻帧的运动/占据变化没有利用；占用预测的时序一致性（预测未来、遮挡推理）不在本文范围——这正是「占用世界模型」路线（本站 4D 重建域）在补的。
  • 复现门槛：无公开代码；λ/β、训练硬件、batch、VFM checkpoint 细节均未给出；只能按论文的模块与超参自行实现。
  • 部署成本：VFM 冻结省了训练，但推理仍要跑 10 亿级基座；车端需要蒸馏/量化/剪枝——论文未讨论。
  • 数据与标定绑定：只在 nuScenes 验证，依赖 SurroundOcc 稠密标签与 nuScenes 相机标定；跨数据集/跨车型泛化未测。

5.3后续方向（本站路线图把它们串成了一条线）

  • 换更强的几何基座：VGGT → DVGT → VGGT-Omega（CVPR 2026）——按本文的结论，底座越强、几何先验越好，占用精度会跟着涨，而框架不用重训。
  • 加时序：把 DVGT 的 temporal 注意力或 MoVieS 式的动态表示接进来，从「单帧占用」走向「4D 占用预测/世界模型」——对应本站 4D 重建域的「占用世界模型」路线。
  • 与驾驶 4D 高斯路线汇合：DrivingRecon 用环视视频前馈 4D 高斯、L4GM 从单目视频出动态高斯——VG3S 的高斯占用解码与它们是同一族表示的两种用法（重建/渲染 vs 占用/感知）。
  • 下游任务：占用是规划/控制的上游；把 VG3S 的占用接进预测与规划，形成「感知 → 占用 → 规划」闭环，是自动驾驶栈的自然延伸。
  • 更好的适配器：HGFA 的三段式是手工设计的；未来可以用 NAS/更通用的 adapter（如 LoRA 式低秩适配）替代，进一步降低每个下游任务的适配成本。
