VGGT：一个 Transformer 直接吐出场景的全部 3D 属性

VGGT: Visual Geometry Grounded Transformer · arXiv 2503.11651 · github.com/facebookresearch/vggt · 17 个数据来源 · CVPR 2025 最佳论文

§0速览卡

核心解读

接着 DUSt3R 的思路往下问一步：两张图的点图能一次回归出来，为什么不是所有图？DUSt3R 每次只看两张图，N 张图要两两跑一遍，再靠全局对齐把碎片拼起来。VGGT 把这件事收进一个 Transformer 里：每张图切成 patch token，再给每帧挂上「1 个相机 token + 4 个寄存器 token」，全部帧的全部 token 拼在一起进网络——24 层注意力，帧内注意力（每帧自己的 token 互相看）和全局注意力（所有帧的所有 token 互相看）逐层交替。24 层走完，每一帧的信息已经在网络内部和所有其他帧交换完毕，出口挂三个头，一次前馈同时输出每帧的相机参数、深度图、点图（每像素一个 3D 点）和跟踪特征。没有两两前馈、没有全局对齐、也没有 BA：传统视觉几何「特征匹配 → 几何求解 → 迭代优化」的整条流水线被一个网络吸收，10 帧重建 0.2 秒量级。整套方法概括起来就是：把全部帧的 token 送进一个 24 层「帧内 / 全局」交替注意力的 Transformer，一次前馈直接输出每帧的相机参数、深度图、点图与跟踪特征——重建不再需要两两前馈与全局对齐，一个网络直接成为 3D 重建的基座。

  • 目标：输入 N 张图（同一场景，1 张、几张到几百张都行），一次前馈输出每帧的相机参数、深度图、点图（每像素一个 3D 坐标）和一组跟踪特征；相机位姿、点图、深度都定义在第 1 台相机的坐标系里。做法是「最小归纳偏置」：网络里没有任何几何约束层（不对极约束、不三角化、不 BA），几何先验全部从 17 个带 3D 标注的数据来源里学出来。帧与帧的信息交换不靠专门的匹配或对齐模块，而是靠注意力本身——一层帧内、一层全局，交替 24 轮（结构见图 0-1）。
    图 0-1 · VGGT 核心机制：每帧图切成 patch token、拼上 1 个相机 token 和 4 个寄存器 token，全部帧的 token 进 24 层「帧内 / 全局」交替注意力；出口三个头一次输出相机、深度、点图和跟踪特征。帧间信息交换全部发生在注意力层里，没有任何匹配或对齐模块。shape 取自官方 VGGT-1B 配置（518×518 输入、patch 14）。
  • 训练：
    • 输入：每个 batch 先随机抽一个数据集、再随机抽一个场景，采 2~24 帧；整个 batch 恒定凑满 48 帧（比如两条 24 帧序列，或六条 8 帧）。图像长边缩到 518 像素，短边裁到 168~518，保持 14 的倍数（对齐 patch 网格）。同一场景内各帧独立做很强的颜色抖动——逼模型对光照变化不敏感。
    • 输出：每帧四样预测——相机参数 ĝ∈[S,9]、深度图 D̂∈[S,H,W]、点图 P̂∈[S,H,W,3]、跟踪特征 T̂；外加两张逐像素不确定性图 ΣD、ΣP：训练时进损失当权重，训完就是模型自报的置信度。
    • GT：相机和深度直接来自数据集（传感器采集、合成引擎、SfM 重建三种来源都有）；点图 = 深度反投影成 3D 点、写进第 1 台相机的坐标系；跟踪真值 = 深度反投影 → 重投影到目标帧 → 保留「重投影深度 ≈ 目标帧深度」的对应点（VGGSfM / Roma 同款协议，全自动，不用人工标）。所有真值先做一次规范：以首相机系表示，再除以场景里所有 3D 点的平均原点距离，把尺度钉死。注意预测端不做这个归一化——网络被迫自己学会输出这个规范尺度（DUSt3R 是两边都归一，VGGT 只在真值上做）。
    • Loss：四项相加，跟踪项压到 0.05 权重；相机、深度、点图三项量级相近，不另外调权重：
      L = Lcam + Ldep + Lpmap + 0.05·Ltrack
      各项的含义（完整推导与论文/代码差异见 §3）：
      Lcam：逐帧比较预测相机 ĝ 与真值 g 的距离——论文明写 Huber 损失，发布代码实际用 L1，并把平移 / 旋转 / 视场分开加权（1 : 1 : 0.5），相机头的 4 轮迭代输出各自算损失、按 0.6 的幂衰减加权（§3.1）；
      Ldep：Σ ‖ΣD ⊙ (D̂ − D)‖ + ‖ΣD ⊙ (∇D̂ − ∇D)‖ − α·log ΣD——第一项管数值、第二项管空间梯度（相邻像素的差，管边缘和平面平滑），第三项是置信度校准；ΣD 是网络自己输出的每像素不确定性（代码里 expp1 激活，恒 ≥ 1），⊙ 是逐元素相乘，∇ 是相邻像素差分，α = 0.2；
      Lpmap：把上式里的深度换成点图——D̂→P̂、ΣD→ΣP，逐像素 3D 距离；
      Ltrack：Σ ‖y − ŷ‖（L1 距离）+ 可见性二元交叉熵——和 DUSt3R 一样，这一项在发布训练代码里没整理完（§3.1）。
    图 0-2 · 训练流程：采样帧 → VGGT 前馈 → 四路预测 → 四项损失（真值由数据集自带标注 + 深度重投影构造）→ 反向传播。图内只放符号，公式与变量解释见训练条与 §3。
  • 推理：
    • 输入：N 张图（1 张、几张、几百张都行），不需要相机参数——不给内参也不给位姿，网络自己估；这也意味着推理端没有任何需要标定的前置步骤。图像预处理：默认 crop 模式（宽缩到 518，高等比缩到 14 的倍数、超过 518 就中心裁），或 pad 模式（长边 518、短边补白成正方形）。不同帧可以先拼成同样尺寸，但代码支持各帧不同 shape。
    • 输出：一次前馈，10 帧约 0.2 秒（H100）。每帧拿到四样东西，各有读法：
      • 点云：两条路——直接取点图头 P̂（每像素一个 3D 点，首相机系）；或取「深度头 D̂ + 相机头 ĝ」反投影回 3D。论文实测第二条更准（ETH3D Overall 0.677 vs 0.709）：把一个难任务拆成深度、相机两个简单子任务，各自都学得更好，拼回来就胜过直接回归。想省算力还可以只开需要的头。
      • 相机：直接读 ĝ = [q 四元数, t 平移, f 视场]；第 1 帧恒等（q₁=[0,0,0,1]、t₁=0），其余帧都在首相机坐标系里。
      • 轨迹：给任意一帧里的查询像素 y_q，跟踪头在特征图 T̂ 上采点、和其他帧做相关，输出它在所有帧的 2D 对应 ŷ_i 和可见性——运动视频里的动态点也能追（特征自带语义，见 §4.4）。
    • 后处理：可选 BA（光束法平差）——拿 VGGT 的预测当初始化（它直接给 3D 点，不需要 VGGSfM 那样的三角化和迭代精化），跑一次 BA 约 2 秒；IMC 摄影旅游数据集 AUC@10 从 71.26 涨到 84.91。不接 BA 也已经是当时的最强前馈结果，BA 只是锦上添花——顺序和传统方法反过来：传统是「先解后优」，VGGT 是「网络先给准初值、优化器收尾」。
    图 0-3 · 推理流程：N 张图一次前馈得到四路输出，点云 / 相机 / 轨迹各有读法；BA 是可选的锦上添花。shape 为官方 VGGT-1B 推理配置。
  • 效果：
    • 定性：输出直接就是可用的彩色点云——包括油画、沙漠这种重复/均匀纹理、甚至两帧几乎不重叠的困难例子（论文图 3、图 10）。1 张图也能跑：此时全局注意力自然退化成帧内注意力，单图重建质量出乎意料地好（论文没专门训过单图，但有演示）。
    • 定量：全部前馈、不接任何后处理——多视图位姿 Re10K AUC@30 85.3 / CO3Dv2 88.2（此前最强 DUSt3R 67.7 / MASt3R 81.8，都还要 7~9 秒的后处理）；DTU 多视图深度 Overall 0.382（DUSt3R 1.741，且赢过多数带 GT 相机的传统 MVS）；ScanNet-1500 两视图匹配 AUC@5 33.9 超过专用匹配器 Roma（31.8）；作为特征喂给 CoTracker，TAP-Vid RGB-S δavg 从 78.9 抬到 84.0；10 帧前馈约 0.2 秒（数字与表见 §4）。
  • 结论：「大 Transformer + 大规模 3D 标注数据 + 多任务联合监督」足以把特征匹配、三角化、BA 这整套视觉几何流水线收进一个网络的隐式计算里：几何后处理第一次从「必需品」降级成「可选项」，而网络的中间特征还能直接拿去支持跟踪、新视角合成这些下游任务——3D 重建从此有了自己的基座模型。

QA 档案

Q：每帧挂的那 4 个「寄存器 token」是干嘛的？相机 token 为什么要备两套（首帧一套、其余帧一套）？
A：寄存器 token 是一类不算输出的「公共工作区」token（做法来自 ViT 的 registers 工作）：网络可以在里面暂存、中转信息，不必强行征用 patch token 当存储，出口直接丢弃。相机 token 则是留给相机参数的专属查询槽位，出口后只喂给相机头。两套的原因：第 1 帧是坐标系原点（位姿恒等）、身份特殊，网络必须随时知道「我在处理参考帧还是普通帧」——首帧 token 和其余帧 token 是两组不同的可学习参数，网络从 token 本身就能读出这个身份。代码里 camera_token / register_token 各存 2 份（形状 (1,2,1,C)、(1,2,4,C)），forward 时按帧序切片展开；4 个寄存器 token 输出即丢，patch_start_idx = 1+4 = 5 只是记号「前 5 个是特殊 token」。
Q：为什么「帧内 + 全局」交替的注意力比纯全局注意力好？跨注意力为什么不用？
A：ETH3D 点图消融（Overall 越低越好）：交替 0.709 ＜ 纯全局 0.827 ＜ 跨注意力 1.061，三种结构的参数量对齐。理解方式：纯全局注意力把所有帧的全部 token 糊进一个池子，帧与帧的 token 争夺注意力预算，单帧内部的结构容易被稀释；交替方案让「帧内层」先把每帧自己的 token 归一化、压紧，再由「全局层」做帧间交换——两件事轮着做，论文的原话是在「跨图融合」和「单图激活归一」之间取平衡。跨注意力每帧都要单独对所有其他帧做注意力，随帧数变多又慢又乱，消融里也最差。（另一个角度：帧内层相当于给每一帧装了一层「先把话在自己家里说清楚再出门开会」的机制。）
Q：点图明明能从深度 + 相机推出来，为什么四个量还要全都监督？推理时又为什么用「深度 + 相机」而不是点图头？
A：训练时全监督的收益有消融背书（ETH3D Overall）：全监督 0.709；去掉相机项 0.834、去掉跟踪项 0.790、去掉深度项 0.727——都变差，相机的贡献最大，深度的贡献最小但仍然有用。直觉：监督就是可微的软约束，从不同侧面对同一份几何反复对齐，共享 backbone 学到的表示更结实（论文：learning to predict these interrelated 3D attributes enhances overall accuracy despite potential redundancies）。推理时反过来做减法：分开预测的深度和相机反投影出的点云，比专门点图头更准（0.677 vs 0.709）——训练时互为老师，推理时挑最好的那条路。这也解释了为什么 VGGT 存的是「过完备」输出：冗余在训练期是养分，在推理期是选项。
Q：相机头论文写「4 层自注意力 + 线性层」，代码里是什么？哪个为准？
A：以代码为准，论文是简化描述。代码里相机头是一个 4 轮的迭代精修器：每轮把上一轮的位姿预测（第 1 轮用学到的空位姿）编码后经 AdaLN（自适应层归一化）调制相机 token，过一个 transformer block，再让 MLP 输出一个增量 Δĝ 累加上去——4 轮得到 4 个越来越准的位姿。训练时 4 轮输出全部算损失（越早的轮次权重越低，按 0.6 的幂衰减，见 §3.1），推理只取最后一轮。位姿编码格式 absT_quaR_FoV = 平移 3 维 + 四元数 4 维 + 视场 2 维 = 9 维。所以「4 层」的说法抓的是主干深度（trunk_depth=4），漏掉的是「迭代累加」这个关键机制。
Q：17 个训练数据集各自的标注从哪来？跟踪真值是怎么造出来的？
A：三类来源：传感器实采（ScanNet、ARKit 式数据）、合成引擎（Kubric、Hypersim、Virtual KITTI、Aria 合成环境等）、SfM 后处理（MegaDepth、DL3DV 等）。相机和深度直接可用。轨迹真值全自动构造：把深度图反投影成 3D 点 → 用相机位姿重投影到目标帧 → 保留「重投影回来的深度和目标帧深度一致」的对应点（能通过深度一致性检查的才认为是真对应）；低相似度帧在采样阶段就排除。整套协议来自 VGGSfM / Roma，不需要任何人工轨迹标注。这也解释了 tracker 为什么能零迁移成本地吃 VGGT 特征——训练时就一直在做「跨帧找同一个 3D 点」这件事。
Q：论文和发布代码有哪些明确出入？复现时按哪个？
A：逐条列（详版见 §3）：① 相机损失论文明写 Huber，代码注释直说「试过，L1 更稳」，实际用 L1；② 代码里相机损失多了分项权重（平移:旋转:视场 = 1:1:0.5）和 4 轮迭代的 0.6 幂衰减，正文没提；③ 深度/点图损失的代码版多一个「不加权 L2 回归项」进总损失，梯度项是多尺度（3 尺度）、可选加权，微调模板里深度用梯度差分损失、点图示例用表面法线损失，还有 0.98 分位过滤；④ 跟踪损失发布代码直接没整理（trainer 会抛 NotImplementedError，文件底部是草稿），论文的 λ=0.05 只是论文值；⑤ 发布 training/config 是 Co3D 微调模板（lr 5e-5、冻结 aggregator、相机权重 5.0、4 卡），不是从零训练配方（论文：lr 2e-4、160K 迭代、不冻结、64×A100 9 天）。复现主训练：超参按论文，数据管线和 track loss 得自己补——这也是这条路线的公认复现代价。
Q：权重和许可状态？想用它做产品行不行？
A：2025-07 起仓库代码许可更新为可商用（明确排除军事用途）；权重分两个——原始 VGGT-1B 仍是非商用，VGGT-1B-Commercial 可商用（在 HF 上填表申请，自动审批，官方称性能相近）。训练代码 2025-07 放出（training/ 目录 + Co3D 微调示例），评测代码在 evaluation 分支，COLMAP 导出脚本可把预测存成标准格式接 BA 或喂给 gsplat 等 3DGS 库。后续 VGGT-Omega（CVPR 2026，见路线图）是官方下一代。

§1Motivation

问题是什么、难在哪、别人怎么解、VGGT 怎么解。

3D 重建的默认形态一直是「优化问题」：给一组照片，解一个最小化重投影误差的非线性方程组（Bundle Adjustment，光束法平差——同时优化所有相机参数和 3D 点坐标，让 3D 点投影回每张照片后和观测到的像素对齐）。学习模块这些年不断渗入——特征匹配用网络、深度用网络——但流程的骨架还是几何优化器：先有初值，再迭代收敛。DUSt3R 把「两张图 → 点图」做成了纯回归，证明了网络能直接输出几何，但它一次只能吃两张图：N 张图要 O(N²) 次前馈，跨图一致性完全靠事后全局对齐，本质还是「网络 + 优化器」的拼装。VGGT 的问题是：能不能把「全部图 → 全部几何量」也做成一次回归？整套方法概括起来就是：把全部帧的 token 送进一个 24 层「帧内 / 全局」交替注意力的 Transformer，一次前馈直接输出每帧的相机参数、深度图、点图与跟踪特征——重建不再需要两两前馈与全局对齐，一个网络直接成为 3D 重建的基座。

1.1面临的问题和难点

几何后处理仍是必需品

哪怕学习模块把匹配和深度都做得很准，最终一致性还是要靠 BA / 全局对齐这类迭代优化来兜底：它们慢（一组图秒级到分钟级）、要调参、失败时不告诉你哪里坏了。

后处理也把「实时」挡在门外：任何需要重建结果的下游（机器人、AR）都得排队等优化器收敛。

两两范式的天花板

DUSt3R / MASt3R 的点图表示很成功，但「一次两张图」的设定有两个代价：跨图一致性只能事后用对齐去找补；帧数一多，O(N²) 的前馈和对齐开销一起涨。

而且模型永远看不到「第三张图」的上下文——信息在成对预测里被切碎了再拼回来，拼缝就是误差来源。

1.2别人是怎么解决的

路线代表工作做法 & 痛点
增量式 SfM COLMAP / PixSfM 特征→匹配→几何验证→增量重建→BA。精确、成熟，但每步独立优化、误差累积；一组图几十秒到小时级，光旅游场景里靠不断加猛料（像素级精化）维持精度。
可微 SfM VGGSfM 把整条 SfM 流程做成端到端可微（含可微 BA），学习与几何深度绑定。仍是「几何为主角」的架构，重建约 10 秒，够准但不够快，且要知道大概的相机模型。
两两前馈 + 全局对齐 DUSt3R / MASt3R 点图回归一次输出深度、位姿、对应，表达力大进步；但一次两张图，多图要两两跑 + 全局对齐（>10 秒），动态图更麻烦。
单任务大模型 DepthAnything / MoGe / LRM 大网络 + 大数据在单个 3D 任务上很强（单目深度、点图、图生 3D），但一个模型只干一件事；几何量之间的互信息被浪费。

1.3VGGT 是怎么解决的

核心思想：不给 3D 设计新结构，把「大 Transformer + 大数据 + 多任务」这套在语言和 2D 视觉里验证过的配方原样搬到 3D。具体三个决定：

  • 最小归纳偏置：网络里不放任何几何模块——没有对极约束、没有三角化层、没有可微 BA。唯一的结构选择是「帧内注意力与全局注意力交替」，目的也只是让信息在「帧内归一化」和「帧间交换」之间平衡。几何规律让网络从 17 个带标注的数据源里自己学。
  • 全部量一起预测（over-complete）：相机、深度、点图、跟踪特征全都要，四路监督同时挂在共享主干上。它们之间有闭式关联（深度+相机=点图），但实验证明「多余」的监督反而是养分（§4.4 消融）；推理端再按需取最准的那条路。
  • 可变帧数、首帧定系：训练时每序列采 2~24 帧、batch 固定 48 帧，所以网络天然适应任意帧数；第 1 帧用一组专属 token 标记为参考帧，所有输出（位姿、点、深度）都写在它的坐标系里——和 DUSt3R 一样的设计，只是这次是整个序列一次进网络。

1.4优点和效果

  • 一个模型覆盖全部几何任务：相机位姿、单目/多视图深度、稠密点云、两视图匹配、动态点跟踪，零样本直接用，不用按任务换模型（§4）。
  • 前馈即 SOTA：10 帧 0.2 秒，性能超过带 7~10 秒后处理的 DUSt3R/MASt3R/VGGSfM；接上 BA 还能再涨一截（IMC AUC@10 71.26→84.91，全程 2 秒）。
  • 特征是通用资产：同一套 backbone 特征喂给 CoTracker 提升动态跟踪、微调后能做前馈新视角合成——3D 基座模型的雏形。
  • 帧数弹性大：1 帧到 200+ 帧同一套权重，显存随时间线性（200 帧 8.75s / 40.6GB，见 §4.5），工程上可分批推理。
  • 结构极简：24 层注意力 + 三个头，没有任何几何专用层——「复杂结构才准」的默认设定被打破。

§2Architecture

先看前馈总图（模块级，每个模块标真实 shape），再按 2.2、2.3 拆主干和三个头。

2.1Overall Pipeline

图 2-1 · VGGT 前馈总流程：DINOv2 切 patch → 每帧拼特殊 token → 24 层「帧内 / 全局」交替注意力 → 三个头出四路预测。shape 取自官方 VGGT-1B 配置（img 518×518、patch 14、dim 1024）。
输入 主干 / 预测头 输出 数据流 监督 / 训练细节
  • 输入侧只做 resize 和颜色增强，没有任何标定要求：训练时随机长宽比（0.33~1.0），推理提供 crop（宽 518、高等比裁）和 pad（长边 518、补白成方形）两种预处理；图像尺寸必须是 14 的倍数（patch 大小 14）。
  • patch 嵌入用 DINOv2（ViT-L/14 带 registers 版）而不是直接上 14×14 卷积：论文附录说两种都试过，DINOv2 效果更好、训练稳定得多，对学习率这类超参不敏感——所以「用预训练的 2D 特征当起点」是 VGGT 藏起来的一个关键前提。
  • 特殊 token 是两组可学习参数：1 个相机 token + 4 个寄存器 token；第 1 帧一套、其余帧共用另一套。出口处寄存器 token 丢弃，相机 token 进相机头，二者都不加位置编码（代码注释明说：位置编码只给 patch token）。
  • 主干不是「每层都留中间结果」：只有层号 4/11/17/23 的中间 token 被缓存（省显存），且缓存的是「帧内输出和全局输出拼接后的 2C=2048 维」版本——DPT 头（输入维 2048）吃的就是这份拼接，这是论文图里看不到的代码细节。
  • 三个头各取各的 token：相机头只取最后一层的相机 token；两个 DPT 头取 4 层缓存的 patch token；跟踪头吃的是「DPT 输出里的跟踪特征图」——即稠密头的中间特征复用，不多开路。
  • 1 张图也能跑：S=1 时全局注意力自然退化成帧内注意力，同一套权重直接工作（论文附录：没专门训练但效果意外地好）。
  • 整个网络的输出统一在首相机系：首帧位姿被钉成恒等（q=[0,0,0,1]、t=0），其它一切（点、深度、其它帧位姿）都相对它表达——和 DUSt3R 同一套约定，只是从两图扩展到 N 帧。

2.2Alternating-Attention 主干

主干的全部设计就一句话：帧内自注意力和全局自注意力交替，各 24 层。但「为什么需要帧内层」值得说透——它是 VGGT 相比「把所有 token 一把塞进全局注意力」最实质的改动：

  • 全局层干「开会」：把 (B,S,P,C) 形状的 token 展平成 (B, S·P, C)——一个 batch 里所有帧的全部 token 连成一条长序列做标准自注意力。任何两帧、任意两个 token 之间都能直接交换信息，多视图三角化所需的跨帧对应就在这一层里隐式学出来。
  • 帧内层干「整理」：把形状展成 (B·S, P, C)，每帧的 token 独立做自注意力。论文的说法是它负责「normalizing the activations for the tokens within each image」——每帧先在自己的上下文里把特征压紧、对齐一次，不让帧间信息把单帧结构淹掉。没有这一层，全局注意力里各帧 token 互相争注意力预算，单图内部的细节会被稀释（消融数字见下）。
  • 为什么不用跨注意力：跨注意力（每帧 query 所有其他帧的 key/value）听起来更直接，但消融里最差（ETH3D Overall：跨注意力 1.061 ＞ 纯全局 0.827 ＞ 交替 0.709，三种结构总注意力层数对齐都是 2L 层），而且开销随帧数线性膨胀。论文原话：交替方案是「跨图融合」和「帧内归一」之间的 balance。
  • 稳定性三件套（代码级）：QK-norm（对 query/key 先归一化再算注意力，防数值爆炸）、LayerScale（每个残差分支乘一个可学习缩放，初值 0.01，深层训练稳定）、2D RoPE（旋转位置编码，frequency 100，给 patch 网格提供坐标感）。加上 bfloat16 和梯度检查点，24×2=48 个注意力块才训得稳、放得下。
  • 参数量与结构细节：每层自注意力 + MLP，dim 1024、16 头、MLP 扩展比 4——就是标准 ViT-L 的配置；帧内块和全局块各自独立 24 份（aa_block_size=1，逐层交替，不是几层一组）。整个网络约 1.2B 参数。
  • 显存瓶颈与工程出口：全局注意力是 O((S·P)²)，帧数越多越贵（200 帧 40.6GB，见 §4.5）；官方提供逐帧（frame-by-frame）推理模式：帧间关系只在主干里，DPT 头本来就逐帧独立——所以显存不够时可以分批过主干、分帧出头，精度不变（论文 appendix 的建议）。

2.3相机 / 稠密 / 跟踪三个头

2.3.1相机头：4 轮迭代精修

  • 输入：主干最后一层的相机 token，每帧一个，形状 [B,S,2048]（拼接后的宽度，代码里相机头 dim_in = 2×1024）。
  • 迭代循环 ×4：第 1 轮从一个可学习的「空位姿」出发；每一轮把上一轮的位姿预测编码后经一个调制网络（SiLU + Linear）产生三组参数（shift / scale / gate），用它们对相机 token 做自适应层归一化（AdaLN，把「当前位姿估计」的信息注入 token），过一层 transformer block，再由一个 MLP 输出 9 维的位姿增量 Δĝ，累加到当前估计上。4 轮下来得到 4 个越来越准的位姿。
  • 激活函数：平移 t 线性输出、四元数 q 线性输出后归一化成单位四元数、视场 f 过 ReLU 保证为正。位姿编码格式 absT_quaR_FoV = 平移 3 + 四元数 4 + 视场 2 = 9 维。
  • 4 个输出全都用：训练时每一轮的位姿都算损失，越早的轮次权重越低（0.6 的幂衰减，见 §3.1）——等于让网络学会「每想一轮就更准一点」；推理只取最后一轮。
  • 论文对照：正文写「四个额外自注意力层 + 一个线性层」，抓的是主干深度（trunk_depth=4）；代码里的「迭代精修 + AdaLN + 增量累加」是论文没有展开的核心机制（代码 vggt/heads/camera_head.py）。

2.3.2两个 DPT 稠密头（深度 / 点图）

  • 结构（DepthAnythingV2 同款 DPT）：取主干缓存的 4 层 token（层号 4/11/17/23，每层都是「帧内+全局」拼接的 2048 维）→ reshape 回 2D 网格（37×37）→ 1×1 卷积投到 [256,512,1024,1024] 四个尺度 → resize 层（×4 上采、×2 上采、原样、×2 下采）统一到同一分辨率 → scratch 融合到 256 维 → refinenet 从深到浅逐级融合（4→3→2→1）→ 卷积输出。
  • 深度头：输出 2 通道 = [深度, 不确定性]。深度过 exp 激活（恒正）；不确定性过 expp1 激活 = 1 + exp(·)，恒 ≥ 1——和 DUSt3R 的置信度 C = 1 + exp(c) 是同一个设计（下界锁 1，不许「弃权」）。
  • 点图头：输出 4 通道 = [x, y, z, 不确定性]。xyz 过 inv_log 激活 = sign(y)·(exp(|y|)−1)——一种对称的对数反变换（正的往正方向指数拉、负的往负方向拉），配合「平均距离归一化」的尺度约定，让输出自然落在合理范围。
  • 两个头吃的是同一份 token：因为主干的中间缓存是「帧内输出 + 全局输出」拼接的，DPT 同时看到两种注意力的产物——帧内层提供的锐利单帧结构、全局层提供的跨帧几何一致性。论文图里画不出来，代码里就藏在 concat 这一行。
  • 逐帧独立：DPT 头对每帧单独出图（帧间关系在主干已解决）——这是「显存不够就分批推理」的工程出口：主干分批过、DPT 分帧出头，结果不变。

2.3.3跟踪头

  • 架构：CoTracker2 的跟踪模块原样搬来，但输入换成 VGGT 自产的特征图 T̂（由 DPT 头的 feature-only 模式输出）——不是外挂一个跟踪模型，是同一套主干顺手长出跟踪能力，训练端到端联合。
  • 流程：查询像素 y_q 在特征图上双线性采样得到它的特征 → 与其它所有帧的特征图做相关（correlation）→ 相关图过自注意力层迭代精修 → 输出它在每一帧的 2D 对应 ŷ_i 和可见性。
  • 不假设时间顺序：和 VGGSfM 的 tracker 一样，输入是无序图片集合也能用（训练数据里大量是无序的照片集）——所以它既能追视频里的动态点，也能对任意两张图做匹配（§4.3 的 ScanNet 实验就是这么来的）。
  • 训练约定：查询点训练时总是取第 1 帧（q=1），推理时任意帧可以当查询帧。

§3Loss

记号约定：预测一律带帽（ĝ 位姿、D̂ 深度、P̂ 点图、Σ̂ 不确定性），不带帽的就是真值（g、D、P、Σ）。四项损失都作用在「首相机系 + 平均点距归一化」的规范尺度上。

3.1四项损失：论文公式 + 发布代码的实际形态

L = Lcam + Ldep + Lpmap + 0.05 · Ltrack
论文 Eq.1。三项几何损失量级相近、直接相加；跟踪项乘 0.05 压权重（λ = 0.05）。下面逐项展开。
Lcam = Σi=1N ‖ ĝi − gi ‖ε
论文 Eq.2，Huber 损失 ‖·‖ε（误差小于 ε 时用平方、超过 ε 时用线性，防离群点主导梯度）。符号：ĝi 第 i 帧的预测位姿编码 [q,t,f]（9 维）；gi 对应真值；N 序列帧数。
发布代码的实际做法（以代码为准）：① 损失换成了 L1——代码注释原话是「论文用的是 smooth L1，但我们发现 L1 更稳」，这是明写的论文/代码差异；② 分项加权，平移 : 旋转 : 视场 = 1 : 1 : 0.5；③ 相机头 4 轮迭代的输出每轮都算损失，按 0.6 的幂做时间衰减（越早的轮次权重越低：0.6³, 0.6², 0.6, 1）；④ 平移损失单项 clamp 到 100 防爆；⑤ 只统计有效点 >100 的帧（point mask 和 > 100）。
Ldep = Σi=1N ‖ ΣiD ⊙ (D̂i − Di) ‖ + ‖ ΣiD ⊙ (∇D̂i − ∇Di) ‖ − α · log ΣiD
论文 Eq.3（深度损失）。主式与点图损失同构；下面逐个符号：
D̂i、Di：第 i 帧的预测 / 真值深度图，[H,W]；
ΣiD：网络自报的每像素不确定性（不确定性图，[H,W]），代码里经 expp1 激活 = 1 + exp(·)，恒 ≥ 1——下界锁 1，和 DUSt3R 的置信度设计同源，不许网络把难像素的权重降到零；
∇：相邻像素的空间差分（横向 + 纵向），这一项让预测的深度形状（边缘、平面）也受监督，不只是逐点数值；
α = 0.2：置信度项与回归项之间的平衡系数；
⊙：逐元素相乘（不确定性图按像素加权）。
代码实际做法：① 总损失里除了「置信度加权 + 梯度」这两项，还单独加了一个不加权的 L2 回归项（‖D̂ − D‖ 直接计入）；② 梯度项做多尺度——在 3 个尺度上（每隔 2s 像素采样）各算一遍再平均；③ 有一个 valid_range = 0.98 的分位数过滤，把最离谱的 2% 损失值截掉防炸；④ 梯度差分单项也 clamp 到 100。论文只展示了主式，代码把「稳」这件事做在了外面。
Lpmap = Σi=1N ‖ ΣiP ⊙ (P̂i − Pi) ‖ + ‖ ΣiP ⊙ (∇P̂i − ∇Pi) ‖ − α · log ΣiP
与深度损失同构：把 D 换成点图 P（每像素一个 3D 坐标，[H,W,3]），不确定性换成 ΣP。代码里梯度项有个变体：微调模板注释示例用 surface normal 损失——把点图当成曲面，用相邻像素的叉积算出 4 个方向上的表面法线，损失是 1 − cos（预测法线与真值法线的夹角），同样带置信度加权。它管的是「局部平面朝向对不对」，比单纯梯度更贴几何。
Ltrack = Σj=1M Σi=1N ‖ yj,i − ŷj,i ‖ + BCE(可见性)
论文 Eq.4/5：yj,i 是第 j 个查询点在帧 i 的真值 2D 位置（由深度反投影 + 重投影构造，见 §3.2），ŷj,i 是跟踪头的预测；M 查询点数、N 帧数；第二项是可见性（这个点在这一帧出不出现）的二元交叉熵，跟 CoTracker2 一致。发布代码状态：这一项没整理完——trainer 里对 track 损失直接 raise NotImplementedError，文件底部只有注释掉的草稿（草稿里有 γ=0.8 的多轮迭代衰减、可见性 BCE、3 像素阈值内的置信度 BCE）。论文的 λ=0.05 是论文超参，复现要自己按草稿补。
图 3-1 · 损失链路：真值由数据集标注 + 深度反投影构造并归一化，四项损失逐项加权求和，反向传播覆盖全网络。

3.2真值规范化与训练配方

为什么要归一化：把场景整体放大或平移，图像本身一点不变——所以「更大的重建」和「更小的重建」都是合法答案。VGGT 的规范化和 DUSt3R 一样：先把一切写进首相机系，再除以「场景里所有 3D 点到原点的平均欧氏距离」，把尺度钉死；`t`、`P`、`D` 都按这个尺度表达。唯一的区别（论文附录专门讨论）：DUSt3R 连预测也归一化，VGGT 只在真值上做——它让网络自己学着输出这个规范尺度。论文说这样收敛没问题，反过来预测端归一化还会引入训练不稳定。

§5Conclusion

5.1这篇论文证明了什么

  • 「大 Transformer + 大数据 + 多任务」可以整体替代几何流水线：17 个带标注的数据源喂一个 1.2B 参数的普通 Transformer，前馈就超过了带 7~10 秒后处理的 DUSt3R/MASt3R/VGGSfM——视觉几何的「匹配、三角化、BA」第一次从必需品降级为可选项。
  • 结构选择是最高杠杆：不设计几何模块，只把注意力拆成「帧内 / 全局」交替，就把多视图信息融合收进了网络内部（消融：交替 0.709 ＜ 纯全局 0.827 ＜ 跨注意力 1.061，参数量对齐）。复杂结构不是精度的前提。
  • 过完备输出是养分而不是浪费：四个量（相机、深度、点图、跟踪）之间有闭式关联，但全都监督反而让点图更准（去掉任一都变差）；推理时还能按场景挑最准的读取路径（深度 + 相机反投影 ＞ 点图头）。「训练时冗余、推理时选择」是个可复用的设计模式。
  • 几何特征是可迁移资产：同一套 backbone 特征喂给 CoTracker 提升动态跟踪、微调后能做前馈新视角合成——VGGT 不只是重建器，是 3D 的基座模型。
  • 工程上真正可复现：训练代码（微调模板）、COLMAP 导出、商业许可、evaluation 分支都放出来了——虽然主训练的完整配方（track loss、数据管线）仍要自己补。

5.2局限（论文自述 + 读代码看出来的）

  • 论文自述三条：不支持鱼眼 / 全景相机；极端输入旋转下重建性能下降；大范围非刚体变形会失败（轻微非刚性还能处理）。
  • 显存与帧数耦合：全局注意力是 O((S·P)²)，200 帧 40.6GB（旧实现）；官方建议显存不够就分批推理——帧间信息只在主干里，分批会牺牲跨批的一致性。
  • 训练成本高：64×A100 × 9 天，个人复现几乎不可能；发布配置只是 Co3D 微调模板，想从零训练要自己补数据管线和跟踪损失（代码里仍是草稿）。
  • 权重许可分叉：原始 VGGT-1B 非商用，商用要申请 VGGT-1B-Commercial；代码 2025-07 起可商用（排除军事用途）。
  • 可微 BA 没进模型：论文附录说试过，训练每步慢约 4 倍，放弃了——所以「优化器」在训练期还是缺席，几何一致性全靠数据规模和注意力隐式学。
  • 不是万灵药：它更强的是一致性和通用性，单目疑难场景（远处小物体等）与同域专门训练的深度网络仍有互有胜负；内参未知虽然能估，但精度会降。

5.3后续方向（本站路线图把它们串成了一条线）

  • 官方下一代：VGGT-Omega（CVPR 2026 Oral，路线图「路线一」节点）：用寄存器（registers）做跨帧信息交换 + 规模扩展到 10B + 自监督训练，Sintel 相机估计比此前最好提升 77%，训练显存约为 VGGT 的 30%。
  • 前馈 + 优化器的混合是现实路线：本文已证明「网络给初值、BA 收尾」1.8 秒能到 IMC 84.91；把可微 BA 放进训练是论文点名的未竟方向。
  • 生态分叉（本站路线图上的邻居）：MASt3R 是两两时代的匹配强化；Fast3R 是同期的多图并发前馈；MapAnything（Meta 2025-09）把输入扩展到单目/多视图/带先验的混合场景并补上度量尺度；DepthAnything3（2025-11）用单个朴素 Transformer 做任意视角空间重建；MonST3R 把点图扩展到动态场景。
  • 4D 与高斯路线：本文的注意力主干与特征正在被下游直接复用——MoVieS（CVPR 2026）用 VGGT 预训练的注意力块做动态 4D 视图合成；VG3S（IROS 2026）冻结 VGGT 特征接高斯占用头，是路线一 × 路线三的汇合点；ReconDrive（2026）把 VGGT 扩成 4D 高斯重建。几何基座 → 动态表示，这是 2026 年最清晰的一条主线。
