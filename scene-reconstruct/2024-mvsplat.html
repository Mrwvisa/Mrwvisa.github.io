MVSplat：用代价体积把前馈 3D 高斯做得又轻又准

MVSplat: Efficient 3D Gaussian Splatting from Sparse Multi-View Images · arXiv 2403.14627 · github.com/donydchen/mvsplat · ECCV 2024 Oral

§0速览卡

核心解读

3D Gaussian Splatting（3DGS）把场景表示成一团带位置、形状、透明度、颜色的高斯，渲染快、质量高；但它和 NeRF 一样要逐场景优化——拿到新照片先跑几十分钟优化。前馈式 3DGS 想省掉这一步：看一眼稀疏输入（两张图）就直接输出高斯。上一代代表 pixelSplat 的做法是「从图像特征里回归一个概率深度分布」——但深度这种几何量，靠纯特征回归并不可靠，点云里飘着一堆浮空高斯，必须再补 5 万步带深度正则的微调才能看。MVSplat 换了个思路：不回归深度，做特征匹配。它按传统多视图立体（MVS）的做法构造代价体积：沿深度方向摆 128 个候选面（平面扫描），把另一张图的特征按每个候选深度 warp 过来、和本图的特征算相关——相关值高的深度就是表面所在地。深度从「匹配」里读出来，比从「特征」里猜出来稳得多；其余高斯参数（形状、透明度、颜色）再并行回归。整套方法概括起来就是：用平面扫描构造跨视图代价体积，把高斯中心定位变成特征匹配问题，深度、协方差、颜色一次前馈全部预测出来——只靠光度监督，12M 参数、0.044 秒出 3D 高斯。

  • 目标：输入 K 张稀疏视图（少到 2 张）+ 对应相机参数（内参 K、旋转 R、平移 t 都要给——这一点和 DUSt3R/VGGT 的免标定路线不同），一次前馈输出 K×H×W 个像素对齐的 3D 高斯（每个像素 1 个，pixelSplat 是 3 个），再用可微光栅化渲染任意新视角。核心要解决的是「高斯中心放哪」：中心错，后面怎么调都救不回来（结构见图 0-1）。
    图 0-1 · MVSplat 核心机制：多视图特征 → 平面扫描代价体积 → softmax 出深度 → 反投影成高斯中心；其余高斯参数并行回归。shape 取自官方 256×256 配置（D=128、特征 4× 下采样、每像素 1 个高斯）。
  • 训练：
    • 输入：每个训练样本是一个场景的 6 帧：2 帧当输入（context）、4 帧当监督目标（target）；分辨率 256×256；相机参数已知。batch size 14（14 个场景，即 14×2 张输入图一起过网络）。两帧输入之间的距离在训练中逐渐拉大（沿用 pixelSplat：先从近处帧练起，再逐步拉到远基线）。
    • 输出：K×H×W 个高斯（每个输入像素 1 个）：中心 μ、透明度 α、协方差 Σ、颜色 c（球谐系数）。
    • GT：只有目标视角的 RGB 图像——没有深度真值、没有点云真值。几何质量完全由「渲染出来像不像」逼出来；能逼得出来，靠的就是代价体积提供的匹配线索。
    • Loss：光度损失，两项相加：
      L = ‖ Î − I ‖² + 0.05 · LPIPS(Î, I)
      符号：Î 是渲染出的目标视角图像（[3,256,256]）；I 是对应真值图像；第一项是逐像素 L2（MSE，权重 1.0），第二项是感知损失 LPIPS（权重 0.05，在 VGG 特征空间比距离，管「看起来像不像」）。两项都是整张图一个标量再回传。
      代码细节：实验配置（config/experiment/re10k.yaml 等）把 LPIPS 设为 apply_after_step: 0，即从第 0 步就参与；而通用损失配置 config/loss/lpips.yaml 默认是 150K 步后才加——复现论文数字要按实验配置，别按默认损失配置。另外代码里存在一个 depth loss（权重 0.25），但主实验的损失组合是 [mse, lpips]，没有用它。
    backbone 用 UniMatch 的预训练权重初始化（仓库默认 checkpoint 文件名带 gmdepth-scale1-resumeflowthings-scannet，即 GMDepth 版本、在 ScanNet/合成数据上预训练过）。附录消融：随机初始化也能训到 26.01 dB（300K 步）/ 26.29 dB（450K 步），对比 UniMatch 初始化的 26.39 dB——预训练是加速收敛的「外挂」，不是能否工作的前提。
    图 0-2 · 训练流程：2 帧输入 → 前馈出高斯 → 渲染 4 个目标视角 → 与真值图像算 L2+LPIPS → 反向传播。没有几何监督，几何质量靠代价体积的匹配线索和渲染梯度共同塑造。
  • 推理：
    • 输入：K 张稀疏视图（2 张起，可更多）+ 相机参数；分辨率 256×256（模型按这个尺寸训练；换分辨率要重新适配）。相机外参、内参缺一不可——这是它和 DUSt3R/VGGT「免标定」路线的根本区别。
    • 输出：K×H×W 个 3D 高斯，直接可渲染任意新视角。速度：编码器 0.043 秒（pixelSplat 0.102 秒），光栅化渲染 0.0015 秒（pixelSplat 0.0025 秒），端到端 0.044 秒——约 22 FPS，渲染本身约 500 FPS。导出的高斯还能存成 .ply 给任意 3DGS 渲染器用。
    • 后处理：没有。前馈出高斯 → 光栅化就是结果；不需要逐场景优化、不需要深度微调（pixelSplat 要额外 5 万步带深度正则的微调才能拿到像样的点云）。
    图 0-3 · 推理流程：两张图 + 相机参数一次前馈出 131,072 个高斯，光栅化渲染新视角；全程无后处理。数字取自论文表 1 与实现附录（单 A100，256×256）。
  • 效果：
    • 定性：重复纹理（窗框）、只在单视图出现的物体（扶手、灯罩）、远景大场景（桥）都没有 pixelSplat 那种明显伪影；导出点云干净——pixelSplat 的点云里大量浮空高斯，要额外微调才勉强能用。
    • 定量：RE10K 26.39 / 0.869 / 0.128（PSNR/SSIM/LPIPS，三项全 SOTA，pixelSplat 25.89 / 0.858 / 0.142）；ACID 28.25 / 0.843 / 0.144；端到端 0.044 秒、12.0M 参数（pixelSplat 125.4M）。零样本跨数据集：RE10K→ACID 28.15 / 0.841 / 0.147（pixelSplat 27.64 / 0.830 / 0.160），RE10K→DTU 13.94 / 0.473 / 0.385（pixelSplat 12.89 / 0.382 / 0.560）——域差越大赢得越多。
  • 结论：把「高斯中心放哪」从「从特征回归深度」换成「跨视图特征匹配」，一个传统 MVS 的代价体积就把前馈 3DGS 的几何质量、参数效率、泛化能力同时抬上去：12M 参数、0.044 秒、纯光度监督，还能零样本跨数据集——前馈 3DGS 从此有了一个又轻又强的基线。

QA 档案

Q：为什么「用代价体积做匹配」比 pixelSplat「从特征回归概率深度」稳？
A：两个层面。① 任务难度：回归深度要求网络从单视图特征里「猜」一个连续的几何量，纯特征没有足够的几何约束；代价体积把「这个深度上另一张图的特征和本图像不像」显式算出来，网络只需要学会读相关峰——这是局部匹配问题，比全局回归简单。② 分布鲁棒性：相关值是相对量（两个特征的夹角余弦），对特征的绝对尺度不敏感；pixelSplat 的深度来自纯特征聚合，特征分布一变（换数据集、换视图数）预测就漂。消融直接量化了第一点：去掉代价体积（w/o cost volume）PSNR 掉 3.56 dB（26.39→22.83）、LPIPS 涨 0.069（0.128→0.197，相对恶化近 50%）；而论文附录把 pixelSplat 的深度分支换成这个代价体积后，pixelSplat 自己也从 25.89 涨到 26.63——说明「匹配」这一招是通用的，不是绑在 MVSplat 架构上的特技。
Q：平面扫描具体怎么算？128 个深度候选怎么取？多视图时怎么办？
A：对每个视图 i：① 在 逆深度域（视差）里把 near~far 均匀切成 D=128 份，得到候选深度 d₁…d_D（逆深度均匀 = 近处密、远处疏，符合透视精度分布）；② 对其余每个视图 j、每个候选深度 d_m，用相机投影把 j 的特征图按 d_m 的假设立体面 warp 到 i 的像素网格上（可微双线性采样）；③ 相关 = ⟨Fⁱ, F^{j→i}_{d_m}⟩ / √C（点积除以通道数开方做尺度归一）；④ 多视图时把每个 j 的相关图逐像素取平均——所以网络对视图数不变，只需要「其它所有视图」这一个集合。得到的代价体积 Cⁱ 形状 [H/4, W/4, D]（64×64×128），存的就是「每个像素在每个候选深度上的匹配分」。softmax 沿深度维归一 → 每个候选一个概率，深度取期望 Σ p_m·d_m（而不是 argmax）——可微、亚像素级、梯度能回传。
Q：高斯参数都是怎么参数化的？中心之外的那些量从哪来？
A：① 中心 μ：深度反投影——用相机内参把像素射成世界射线，乘深度（相机系）再转到世界系；代码里每个高斯还有一个学习到的亚像素偏移（2 通道，sigmoid 到 [0,1] 减 0.5，乘一个像素的尺寸），微调中心位置。② 尺度 s：3 通道，sigmoid 映射到 [0.5, 15] 的「相对尺度」，再乘当前深度和一个由内参+像素尺寸算出的因子（0.1·K⁻¹·pixel_size 求和）——所以高斯在世界里的实际大小和「这个像素能覆盖多大」耦合，近处小、远处大。③ 旋转：4 通道四元数，归一化成单位四元数；协方差 Σ = Rᵀ diag(s²) R 再旋转到世界系。④ 颜色：球谐系数 degree 4（每个通道 25 个系数，共 75 个），初始化时高阶项被 mask 压小（先学 DC 颜色，再学视角相关），同样旋转到世界系。⑤ 透明度：论文说「从匹配置信度用两层卷积预测」——代码里是深度精化 U-Net 的输出再过一个两层卷积头（to_disparity），输出「深度增量 + 密度 logits」，sigmoid 成密度，再经 map_pdf_to_opacity 映射（默认配置下这个映射是恒等，即透明度≈匹配概率密度/每像素高斯数）。⑥ 每个像素默认 1 个高斯（可调 3 个：PSNR 26.39→26.54，但渲染 0.0015→0.0023 秒）。
Q：只有光度监督，几何为什么不会烂？为什么 pixelSplat 需要额外深度正则微调，MVSplat 不需要？
A：因为几何线索被显式放进网络结构里了，不用全靠渲染梯度去「顿悟」。代价体积的相关峰直接指明表面在哪，深度期望把这个峰变成可微的亚像素深度；渲染损失只需要微调「峰准不准、高斯形状合不合适」，不用从零学几何。pixelSplat 的深度来自特征回归，没有这样的结构化先验，渲染损失对几何的约束又弱（不同深度可以渲染出相似图像），所以点云里浮空高斯多，必须靠额外的深度正则和 5 万步微调把几何拉回来。消融也印证：去掉代价体积后，MVSplat 自己也会掉到 22.83 dB——光度监督本身撑不起几何，撑起来的是「匹配线索 + 光度微调」的组合。
Q：视图数可变是怎么做到的？训练只有 2 视图，测试给 3 视图为什么反而更好？
A：两个模块都写成「对其它视图逐个处理再聚合」，天然与视图数无关：代价体积对每个 j 的相关图求平均；Transformer 的 cross-attention 让每个视图 query 其它所有视图（同一套可学习参数，视图数不参与形状）。所以训练时 2 视图，测试 3 视图直接能跑，而且更多视图意味着更多匹配证据，深度更稳：DTU 上 3 视图 PSNR 从 2 视图的 13.94 涨到 14.30。pixelSplat 的 Epipolar Transformer 与纯特征聚合绑定了「2 视图」的训练分布，硬扩展到 3 视图反而掉（12.52 对 12.89）。
Q：论文和发布代码有哪些出入？复现时注意什么？
A：① LPIPS 起始步：论文只说损失是 L2 + 0.05 LPIPS；通用配置 config/loss/lpips.yaml 默认 150K 步后才加 LPIPS，但论文实验配置（config/experiment/*.yaml）改成 apply_after_step: 0——按实验配置复现。② 代价体积候选数：config/model/encoder/costvolume.yaml 默认 D=32，实验配置覆盖为 128——论文写的是 128。③ 透明度：论文说「从匹配置信度用两层卷积预测」，代码里是深度精化 U-Net 特征接两层卷积输出「深度增量 + 密度 logits」，密度 sigmoid 后经一个（默认恒等的）映射函数变透明度——不是直接拿 max 概率过卷积。④ 亚像素偏移：代码里每个高斯中心有学习到的亚像素偏移，论文没提。⑤ batch size：config/main.yaml 默认 4，实验配置 14——论文的 14 对。⑥ 损失里存在一个未启用的 depth loss（权重 0.25），主实验没用。复现时认准 config/experiment/re10k.yaml 这一套覆盖值。
Q：它的适用边界在哪？和站内 DUSt3R / VGGT 是什么关系？
A：边界：必须有相机参数（不能免标定）；分辨率固定 256（更高分辨率要重训/适配，后续 MVSplat360、PanSplat 在补）；数据集只在 RE10K 上训过（场景级室内为主），复杂室外/动态场景未验证；非朗伯面（玻璃、镜面）会失败（论文附录）。和免标定路线的关系：DUSt3R/VGGT 解决「没有相机参数 → 一次性出几何」，MVSplat 解决「有相机参数 → 更快更省地出可渲染高斯」——两者可以串联：先用 VGGT 估位姿，再喂 MVSplat 出高斯。这也正是路线图上「前馈几何基座」与「前馈 3D 高斯」两条线并行的原因：一条管几何与位姿，一条管可渲染表示。

§1Motivation

问题是什么、难在哪、别人怎么解、MVSplat 怎么解。

3DGS 把场景变成几十万个高斯，光栅化渲染又快又像，是当下最实用的新视角合成表示。但它继承了一个老问题：每个场景都要单独优化——给定一组照片，先跑几十分钟把高斯的位置、形状、颜色拟合出来，才能渲染。前馈式 3DGS 要省掉这一步：输入几张图，网络直接输出高斯。这条路上真正难的不是颜色，而是高斯中心放哪——中心错了，渲染损失再优化也只能把错误几何渲染得好看一点，点云本身是烂的。SplatterImage 用单图回归，只适合物体级（单视图推断完整 3D 本来就病态）；pixelSplat 用双图，但深度是从图像特征里回归一个概率分布——特征回归几何不可靠，点云里浮空高斯成片。MVSplat 的判断是：深度不该「回归」，该「匹配」——这正是传统多视图立体（MVS）的成熟思路，把它搬进前馈网络就行。整套方法概括起来就是：用平面扫描构造跨视图代价体积，把高斯中心定位变成特征匹配问题，深度、协方差、颜色一次前馈全部预测出来——只靠光度监督，12M 参数、0.044 秒出 3D 高斯。

1.1面临的问题和难点

3DGS 的「逐场景优化税」

3DGS 原版每个场景都要从点云初始化开始，花几十分钟做可微光栅化优化；换一个场景全部重来。实时应用（机器人、AR、数据合成）等不起，也没法把优化搬进在线流程。

前馈化能一次训练、处处推理，但把「优化出来的几何」换成「网络直接给的几何」，质量容易掉——这是整条路线的核心矛盾。

高斯中心定位是关键瓶颈

单视图前馈（SplatterImage）只能做物体级：一张图推完整 3D 本身就多解，场景级更不可能。双视图（pixelSplat）把问题降成双目立体，但它从特征回归概率深度——特征没有几何约束，预测的分布不可靠，点云浮空严重。

而且这类纯特征方法对特征分布敏感：换个数据集、换个视图数，性能就掉（附录的跨数据集实验直接把差距量化了）。

1.2别人是怎么解决的

路线代表工作做法 & 痛点
前馈 NeRF 类 pixelNeRF / MuRF / GPNR / AttnRend 从图像特征回归辐射场，再体渲染。质量尚可但渲染慢（0.186~13 秒/张），特征是全局池化的，空间精度有限。
单视图高斯 SplatterImage U-Net 逐像素回归高斯，单物体重建快且不错；但单视图推断完整 3D 天生多解，场景级一塌糊涂。
双视图概率高斯 pixelSplat Epipolar Transformer 聚双视图特征，回归每像素概率深度再采样。125M 参数、0.104 秒；几何质量差、浮空高斯多，要额外 5 万步深度正则微调。
传统多视图立体 MVSNet / UniMatch 平面扫描 + 代价体积是几何重建的标准答案，精度高；但逐场景优化、需要稠密视图，不是前馈生成模型。

1.3MVSplat 是怎么解决的

核心思想：把 MVS 的代价体积搬进前馈网络，让高斯中心从「跨视图特征匹配」里来，而不是从「单/双视图特征回归」里来。具体拆成四个决定：

  • 高斯中心 = 匹配出来的深度：平面扫描摆 128 个候选深度，把其它视图的特征 warp 过来算相关，softmax 出概率、取期望得到亚像素深度，再反投影成世界系里的高斯中心。相关峰在哪，表面就在哪——这是「读」出来的几何，不是「猜」出来的。
  • 其余参数并行回归：尺度、旋转、球谐颜色都由卷积头从「图像特征 + 精化后的代价体积 + 原图」预测；透明度从匹配密度里来。中心定位与表观参数解耦，各自学各自的。
  • 纯光度监督：训练只用渲染图像与真值图像的 L2 + LPIPS，不用深度/点云真值。几何可信度来自代价体积的结构先验，不靠额外监督硬灌。
  • 效率优先的结构取舍：特征提取用 Swin 局部窗口注意力（不用 Epipolar Transformer 的极线采样）；代价体积精化用 2D U-Net（不用 3D 卷积）；每个像素只出 1 个高斯（pixelSplat 是 3 个）。三处一起把参数压到 12M、端到端 0.044 秒。

1.4优点和效果

  • 质量与效率同时 SOTA：RE10K 26.39 / 0.869 / 0.128、ACID 28.25 / 0.843 / 0.144，参数 12.0M（pixelSplat 125.4M，约 1/10），端到端 0.044 秒（pixelSplat 0.104 秒，约 1/2.4），22 FPS。
  • 纯光度监督就出干净几何：不需要 pixelSplat 那种 5 万步深度正则微调；导出的 .ply 点云可直接用。
  • 零样本泛化强：RE10K（室内）训的模型直接测 ACID（航拍室外）28.15 / 0.841 / 0.147、DTU（物体）13.94 / 0.473 / 0.385——域差越大赢 pixelSplat 越多；ACID 上的零样本结果甚至略超 pixelSplat 在 ACID 上训练的模型（28.15 vs 28.14）。
  • 视图数可变：训练 2 视图、测试 3 视图直接可用，DTU 3 视图 14.30 反而更好。
  • 可扩展：后续 MVSplat360（360° 场景、5 视图）、DepthSplat（DL3DV-10K、12 视图）、PanSplat（4K 全景）都是在它上面接着长出来的——本站路线图「前馈 3D 高斯」线上的 MVSplat360 节点就是它的直系后续。

§2Architecture

先看总图（模块级、带真实 shape），再拆特征/代价体积（2.2）、深度精化（2.3）、高斯参数与渲染（2.4）。

2.1Overall Pipeline

图 2-1 · MVSplat 前馈总流程：多视图特征 → 逐视图代价体积（平面扫描）→ softmax 期望深度 → 深度精化 → 高斯参数 → 光栅化。shape 取自官方 256×256 配置（D=128、特征 4× 下采样）。
输入 特征 / 代价体积 / 高斯头 输出 数据流 监督 / 训练细节
  • 输入是「图像 + 相机投影矩阵」成对出现：Pⁱ = Kⁱ[Rⁱ|tⁱ]，内参/外参都要；网络不接受无标定输入。
  • 特征分辨率固定在 1/4（256→64），代价体积也在 64×64 上算，最后上采回 256×256——精度和显存的折中：128 个深度候选 × 64×64 已经是一张 64×64×128 的三维张量。
  • 每个视图一份代价体积（K 份），深度也逐视图预测；高斯参数在 256×256 全分辨率上逐像素出。
  • 所有模块都对视图数「无感」：相关对其它视图求平均、cross-attn 对其它视图逐一套用——训练 2 视图，推理给更多也能跑。
  • 参数量 12.0M 的构成：大头是 6 层多视图 Transformer 和两个 U-Net；没有 3D 卷积、没有大 ViT backbone——这是它比 pixelSplat 小一个数量级的原因。

2.2多视图特征与代价体积

这一段是整篇论文的重心：怎么把「两张图 + 相机参数」变成一个能直接读出深度的三维张量。

  • CNN 部分：6 个残差块，前 2 块保持 256×256，后 4 块每 2 块用 stride 2 下一次采样（两次共 4×），输出 [K,128,64,64]。浅、窄、没有大 backbone——分辨率降到 1/4 是后面代价体积能承受 128 个深度候选的前提。
  • Transformer 部分：6 个堆叠块，每块 = 一层 self-attention + 一层 cross-attention。用的是 Swin 的局部窗口注意力（特征按 2×2 切窗，窗口内做注意力，逐层交替移位窗口），不是 pixelSplat 的极线采样（Epipolar Transformer）——省掉了沿极线采样这一步，附录测得同样精度下 0.038 秒 vs 0.055 秒。cross-attention 让每个视图 query 其它所有视图，参数与视图数无关。
  • 代价体积构造（以视图 i 为例）：在逆深度域里取 128 个候选 d_m；对其它每个视图 j，把 Fʲ 按「假设深度 d_m」用相机投影 warp 到视图 i 的像素网格（双线性采样，越界补零）；算相关 ⟨Fⁱ, F^{j→i}_{d_m}⟩/√C（点积除通道数开方）；多个其它视图的相关图逐像素平均；把所有候选堆起来得到 Cⁱ ∈ ℝ64×64×128。它编码的就是「每个像素在每个候选深度上，和别的视图有多像」。
  • 为什么用逆深度：逆深度（视差）的均匀采样在近处更密、远处更疏，和透视投影的精度分布一致；near/far 是 1/100 时，128 个候选在视差尺度上等距。
  • 代价体积精化：原始相关在弱纹理区不可靠（哪里都不像）。用一个轻量 2D U-Net 精化：输入是「Cⁱ 拼接 Fⁱ」（128+128=256 通道），输出残差 ΔCⁱ 加回原体积；U-Net 通道宽 128，下采 2 次，在 4× 下采样层加一个 self-attention（把不同视图的代价体积摊平后一起注意）；最后用 CNN 上采样器把精化后的体积升到全分辨率 Ĉⁱ ∈ ℝ256×256×128。
  • 消融意义：去掉代价体积（直接回归特征）PSNR 掉 3.56 dB（26.39→22.83）、LPIPS 从 0.128 涨到 0.197；去掉 U-Net 精化掉 0.67 dB（26.12→25.45）。代价体积是「必选件」，U-Net 是「补弱纹理区」的关键增强——没有匹配的区域（单视图可见部分）只能靠 U-Net 把图像细节映射进高斯。
  • 代码细节：基础配置里 num_depth_candidates: 32，实验配置（re10k/acid/dtu）覆盖为 128——论文数字对应后者；相关卷积前还会把 Fⁱ 拼进输入通道（论文正文没提，代码里是 concat），精化后又加了一个残差连接 corr_refine_net(in) + regressor_residual(in)。

2.3深度估计与精化

  • 粗深度：沿深度维对 Ĉⁱ 做 softmax，得到每个候选深度的概率 p_m；深度取期望 Vⁱ = Σ p_m·d_m（而不是 argmax）。期望的好处：可微、亚像素精度、梯度能回传到整个代价体积；argmax 不可导且只能落在候选格点上。同时把 max p_m 保留下来当「匹配置信度」（这个量后面还要用）。
  • 深度精化 U-Net：粗深度是 64×64 上采来的，边缘糊、细节差。再过一个轻量 U-Net：输入 = 原图（3 通道）+ 投影后的特征（32 通道）+ 粗深度（1）+ 匹配置信度（1），4 次下采样（5 个层级），在 16× 下采样层加跨视图注意力，输出 2 通道——深度增量 Δ视差 + 密度 logits。细视差 = 粗视差 + Δ，再 clamp 到 [1/far, 1/near]，深度 = 1/细视差。
  • 为什么这一步值 0.27 dB：26.12（base）→ 26.39（+refine）。代价体积在「只有单视图能看到」的区域没有匹配，粗深度只能瞎猜；精化 U-Net 直接看原图的高频细节，把这些区域的深度往回拉——论文的定性图里，左右两侧单视图区域的改善最明显。
  • 输出：每视图一张 [256,256] 深度图；配上相机内参/外参就能反投影成世界系点云，直接当高斯中心。

2.4高斯参数与渲染

  • 每像素 1 个高斯：每个输入像素恰好贡献 1 个高斯（pixelSplat 是 3 个）。2 张 256×256 输入 → 131,072 个高斯。附录消融：改 3 个/像素能涨到 26.54 dB，但渲染从 0.0015 秒涨到 0.0023 秒——为了速度选 1 个。
  • 中心 μ：像素射线 × 深度（相机系）→ 世界系；代码里额外预测一个 2 通道亚像素偏移（sigmoid 到 [0,1] 再减 0.5，乘像元尺寸），让中心不锁死在像素格点上。论文没提这个细节。
  • 尺度 s：3 通道，sigmoid 映射到 [0.5, 15] 的「相对尺度」，再乘深度和像素足迹因子（0.1·K⁻¹·pixel_size 求和）——高斯在世界里的绝对大小和「它覆盖的像素在空间中多大」挂钩，近大远小自动成立。
  • 旋转：4 通道四元数，归一化成单位四元数；协方差 Σ = Rᵀ diag(s²) R（R 由四元数构造），再整体旋转到世界系（相机到世界的旋转）。
  • 颜色：球谐系数 degree 4（每通道 25 个系数，共 75 个）。初始化时用一个 mask 把高阶项压到 0.1×0.25^degree——先学与视角无关的 DC 颜色，再慢慢学长视角相关项；SH 也按世界系旋转。
  • 透明度 α：论文写「从匹配 max 概率用两层卷积预测」；代码实际是深度精化 U-Net 的特征接两层卷积（to_disparity），输出「深度增量 + 密度 logits」，密度 sigmoid 后经 map_pdf_to_opacity 映射（默认配置 initial=final=0，映射退化为恒等，于是透明度≈密度/每像素高斯数）。每一轮训练里 opacity 的映射函数是固定的，不另加监督。
  • 渲染：所有高斯送入 3DGS 可微光栅化器，渲染目标视角的 RGB。渲染本身约 0.0015 秒/帧（~500 FPS），端到端 0.044 秒的主要开销在编码器。

§3Loss

记号：预测的渲染图 Î，真值目标视角图像 I（都是 [3,256,256]）。整个训练只有光度监督。

3.1损失与逐符号解释

L = ‖ Î − I ‖² + 0.05 · LPIPS(Î, I)
论文 Eq.6，两项相加：
Î：用前馈预测的高斯渲染出的目标视角图像（可微光栅化）；
I：目标视角的真值 RGB 图像；
‖·‖²：逐像素 L2（MSE），权重 1.0——管数值和结构；
LPIPS(·,·)：感知损失（把两张图送进 VGG 提特征，在特征空间算加权距离），权重 0.05——管「看起来像不像」；LPIPS 的梯度侧重纹理与语义，会把高斯往「视觉上合理」的方向推。
训练时每个场景有 2 个输入视图、4 个目标视图，损失在 4 张渲染图上平均。
  • 没有几何项：没有深度损失、没有点云损失、没有匹配损失。几何完全靠「代价体积的结构先验 + 渲染梯度」撑起来——这是它能只用现成视频数据集（只有 RGB）训练的原因。
  • 代码里的 LPIPS 时间表：通用损失配置里 LPIPS 默认 apply_after_step: 150_000（先只练 L2，后期再加感知项）；但论文的实验配置全部覆盖成 0——从第 0 步就加。复现论文数字请用实验配置。
  • 未使用的 depth loss：仓库里有一个现成的深度损失（权重 0.25），主实验没有启用；它只在想用稠密深度真值时才有意义。

§5Conclusion

5.1这篇论文证明了什么

  • 关键瓶颈是「高斯中心放哪」，解法是换问题形式：把中心定位从「从图像特征回归深度」换成「跨视图特征匹配」，代价体积的匹配峰给出了可靠的几何证据——去掉代价体积 PSNR 掉 3.56 dB，装上它 pixelSplat 也能涨 0.74 dB。同一个几何问题，换一种表述（匹配 vs 回归）就是质量与效率的分水岭。
  • 结构取舍同样重要：不用 3D 卷积（2D U-Net 精化）、不用极线采样（Swin 局部窗口）、每像素 1 个高斯——三处一起把参数从 125.4M 压到 12.0M、端到端从 0.104s 压到 0.044s，同时质量还更高。前馈 3DGS 的「重」不是必需的。
  • 纯光度监督也能出干净几何：几何线索被显式编码在代价体积里，渲染梯度只需要微调，不需要额外的深度真值或正则微调（pixelSplat 需要 5 万步）。
  • 相对相似度带来跨域泛化：RE10K→ACID/DTU 零样本都赢，域差越大赢得越多；ACID 零样本甚至超过在 ACID 上训练的 pixelSplat。匹配是「相对量」这个性质，是泛化的物理来源。
  • 视图数无感：训练 2 视图、测试 3 视图反而更好——聚合式设计（相关平均、cross-attn 对其它视图）让模型天然支持任意视图数。

5.2局限（论文自述 + 读代码看出来的）

  • 必须有相机参数：输入要求 P = K[R|t] 全给；没有位姿就先要跑 SfM / DUSt3R / VGGT 之类的几何前端。这是它和免标定路线（DUSt3R、VGGT）的根本分工。
  • 分辨率固定 256×256：模型按 256 训练和评测；更高分辨率需要重新适配/训练（后续 MVSplat360、PanSplat 在补）。
  • 训练数据只有 RealEstate10K（部分实验加 ACID）：场景多样性有限，野外复杂场景（大尺度、强光照、非刚性）没有验证；论文自己把「规模化训练数据」列为未来方向。
  • 反射/非朗伯面会失败：玻璃、镜面、窗户这类不满足朗伯假设的表面，匹配和渲染都不可靠（附录失败案例图）。
  • 静态场景假设：动态物体（行人、车辆）没有专门机制，会当成静态几何硬拟合——这也是为什么后来的 4D 路线（本站「前馈 4D 高斯」）要另起炉灶。
  • 表达力上限：每像素 1 个高斯是效率取舍；3 个能涨 0.15 dB 但渲染慢 53%。要更高质量需要别的表示或更多基元。

5.3后续方向（本站路线图把它们串成了一条线）

  • MVSplat360（NeurIPS 2024，路线图「前馈 3D 高斯」节点）：把 MVSplat 扩到 360° 大场景——5 个稀疏视图输入，用视频扩散模型补全未见区域，渲染稳定视角的视频。
  • DepthSplat（CVPR 2025）：在 DL3DV-10K 上扩展到 12 个输入视图，处理更复杂的场景。
  • PanSplat（CVPR 2025）：层次化球面代价体积 + 两步延迟反传，把分辨率推到 4K 全景。
  • 与免标定几何基座串联：先用 DUSt3R / VGGT 从无标定图像估出位姿与深度，再喂 MVSplat 出可渲染高斯——「几何前端 + 高斯后端」是 2025-2026 年最实用的组合拳。
  • 数据规模化：论文展望把训练集从 RealEstate10K 扩到多数据集混合，进一步提升野外泛化。
