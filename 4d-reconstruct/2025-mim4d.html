MIM4D：时空双重掩码的视觉预训练范式

MIM4D: Masked Modeling with Multi-View Video for Autonomous Driving Representation Learning · arXiv 2403.08760 · github.com/hustvl/MIM4D · nuScenes · IJCV 2025

§1Motivation

问题是什么、难在哪、别人怎么解、MIM4D 怎么解。

自动驾驶的视觉骨干网络高度依赖预训练，但监督式 3D 标注太贵、难以规模化；自监督路线又大多停留在单帧或单目，白白丢掉了多视角视频里的时序信息。驾驶场景本质是动态的，遮挡关系、物体运动、自车位移都要靠时间维度才能看清，单帧预训练天然缺这一课。MIM4D 的思路是在多视角视频上同时做空间和时间两个域的掩码建模：空间域用 3D 可微体渲染把被掩掉的几何信息补回来，时间域随机丢掉一帧的特征、从剩余帧序列把它重建出来。整套方法概括起来就是：在多视角视频上做空间+时间双重掩码重建的预训练范式，用 3D 渲染补几何、用时序重建补动态场景流。监督信号完全来自传感器数据本身，不需要任何 3D 标注。

1.1面临的问题和难点

单帧预训练看不到动态

UniPAD 这类渲染式预训练在单帧上工作，感知不到场景流和运动物体。动态场景里"上一秒被遮住的东西这一秒在哪"是核心信息，单帧方法结构上就学不到。

时序监督从哪来

想加时序就得有跨帧对应关系。光流估计在自动驾驶场景噪声大，逐像素监督不现实；直接用未来帧监督当前特征又缺一个把"哪个像素对应场景哪个点"讲清楚的可微桥梁。

1.3MIM4D 是怎么解决的

核心是把"掩码-重建"同时开在两个域。输入是连续 4 个时刻的多视角视频（cam_sweep_num=4），图像先过 MaskConvNeXt 做 patch 级掩码（mask_ratio=0.3），这是空间域的掩码；每帧独立过 LSS 体素池化得到 4 份特征场后，时间域再随机丢弃其中一帧的特征，用 history decoder（一个 4 层 transformer）从剩余帧特征里把它重建出来——跨帧对应靠 ego-motion 把历史帧的 lidar 坐标系变换到当前帧图像（代码里的 keylidar2sweepimg），这就是连续场景流的落地形式。重建出的融合特征场过 Conv3d 降通道后，交给与 UniPAD 同构的 NeuS 渲染器：渲染当前帧的 RGB 和深度，也渲染到相邻帧的视点算跨帧一致性。梯度沿渲染链一路回传到图像骨干。

1.4优点和效果

  • 双重掩码互补：空间掩码逼网络学几何补全，时间掩码逼它学场景动态，一个管"看全"一个管"看懂变化"。
  • 零 3D 标注：监督全部来自图像像素和 LiDAR 投影深度，天然可规模化到车队数据。
  • 骨干无关：预训练完的 ConvNeXt 可以直接装进 CVT、PETR、BEVDet4D、Sparse4Dv3 等框架涨点。
  • 时序窗口收益未饱和：窗口从 1 帧加到 5 帧，mAP 18.2→20.1（Table 5），论文判断更大显存还能继续涨。
  • 效果预告：UVTR 检测框架上 32.2 mAP / 31.8 NDS，比 ImageNet 初始化 +9.2 mAP，比 UniPAD +0.8 mAP / +1.1 NDS，细节见 §4。

§2Architecture

先看总图（模块级，每模块标真实 shape），细节留给三个子模块小节。整个代码库构建在 UniPAD（UVTR）之上，渲染器部分两者同构。

2.1Overall Pipeline

图 2-1 · MIM4D 预训练总流程。shape 与超参取自官方 config（uvtr_convnext_s_vs0.075_pretrain.py），B 为每 GPU batch（=1）。
输入 编码器 掩码建模/渲染解码器 输出 监督/控制流
  • 相机视频链路：4 个时刻的 6 目图像 → MaskConvNeXt-S 做空间掩码（30% patch）→ FPN 降维到 256 + ComplexDepth 出深度分布 → 每帧独立过 Uni3DVoxelPoolDepth（LSS）落进统一体素栅格 [180,180,5]（0.6×0.6×1.6m）。
  • 时域掩码：4 个 sweep 的特征场先各自 ego-motion 对齐到 key 帧（shift_voxel_feature_hop），history decoder 从对齐后的特征重建被丢的 sweep，输出融合特征场。
  • 渲染链路：融合场 Conv3d 3×3×3 压到 32 通道 → NeuS 渲染器（SDF 头 32→17、RGB 头 54→3、隐宽 16，72+24 采样点）不只渲染当前帧，还渲染到相邻帧视点，算跨帧一致性。
  • 监督全部免标注：RGB GT 是图像像素，深度 GT 是 LiDAR 投影；梯度沿渲染 → 插值 → LSS → FPN 一路回传到 ConvNeXt 骨干。
  • 预训练交接：收敛后拿 ConvNeXt 权重接下游检测/分割/建图框架微调（§4）。

§2.2Spatial MIM

  • 掩码做在 patch 级：mae_cfg 里 downsample_scale=32、mask_ratio=0.3——800×480 的图按 32 倍下采样成 15×25 的 token 网格，随机掩 30%，掩码 token 不可学习（learnable=False），逼编码器从邻域 patch 推断被掩内容。
  • 骨干不是从零开始：ConvNeXt-S 用 ImageNet-1k 官方权重初始化（init_cfg 指向 convnextS_1kpretrained），drop_path 0.2、首层 stage 冻结——2D 先验 + 3D 渲染监督的组合拳。
  • 深度头管分布不管值：ComplexDepth 输出每个像素 60 档深度分布（frustum 25×15×60，深度 1–60m、0.5m 一档），LSS 按分布加权散射进体素，这是标准的 Lift-Splat 结构。
  • 4 帧各自独立池化：sweep_fusion='None'、keep_sweep_dim=False——时序融合不在这步做，留给 temporal MIM，两件事解耦。

§2.3Temporal MIM

  • 时域掩码 = 随机丢一帧：对 4 份帧级特征场随机置空 1 份，从剩余 3 份把它重建出来——论文里 temporal domain masked modeling 的落地形式，丢的帧数据本身仍然参与监督（渲染相邻帧时当 GT）。
  • 跨帧对应靠 ego-motion：代码用 keylidar2sweepimg 把历史帧的 lidar 坐标系变换到当前帧图像坐标系，运动物体对不上的部分就是要学的"场景流残差"——这就是摘要里 continuous scene flow 的实现载体。
  • BiTemporalPredictor_longshort 双分支：短程分支 2 层 TemporalDecoder @128 维（4 头、TemporalCrossAttention、FFN 256）管相邻帧细节，长程分支 2 层 @64 维（2 头、FFN 128）管跨帧趋势，reduction=2 降采样后再融出——输入 160 = 32 通道 × 5 个 z 切片在 BEV 180×180 上展平成通道，比骨干小一个量级，只干"帧间补全"。
  • 逐 key 帧滚动：get_adj_loss_hop 对 new_id_list 里每个 key 帧循环——每次把全部 sweep 特征对齐到该帧、BiTemporal 重建、再渲染到该帧视点算 rgb_loss_adj / depth_loss_adj（×10，与当前帧同权重）。
  • 这条链路可选：HOP=True 才启用；数据里 sweep 数不足 4 时自动退回单帧模式（is_hop=False 分支），单帧模式等价 UniPAD。

§2.4Volume Rendering

  • 渲染器与 UniPAD 逐项一致：SDF 头 in 32 / out 17（1 距离 + 16 几何特征）/ 隐宽 16 / 5 块；RGB 头 in 54（方向 3 + 场特征 32 + 法向 3 + 几何 16）/ out 3 / 3 块；UniformSampler 72 点 + 表面加密 24 点 = 96 点。差异只在 MIM4D 拿融合后的时序特征场来查。
  • 新增相邻帧渲染（HOP）：当前帧特征除了渲染自身视点，还沿相邻帧的 ray 渲染出 rgb/depth（代码里的 rgb_loss_adj / depth_loss_adj），与相邻帧真实像素比——静态世界应该渲染一致，对不上的地方就是运动，网络被逼着把动态学进特征。
  • ray 采样合并点云先验：point_nsample=512、point_ratio=0.5、merged_nsample=512——一半 ray 从有 LiDAR 返回的像素采（深度 GT 稠密），一半随机采，兼顾监督密度和覆盖面。

§3Loss

L = λrgb·L1(Ŷrgb, Yrgb) + λdepth·L1(Ŷdepth, Ydepth),   λrgb = λdepth = 10
论文 Eq.（渲染重建损失）。当前帧与相邻帧各算一份，相邻帧项在代码里是 rgb_loss_adj / depth_loss_adj，形式相同、GT 换成 ego-motion 对齐后的相邻帧像素与深度。权重 10/10 直接取自 config（loss_cfg.weights）。
图 3-1 · 损失流：只有渲染重建 L1 在带梯度，LSS 深度分布的辅助深度损失被显式置零。
  • 启用的就两项：渲染 rgb_loss=10.0、depth_loss=10.0（config loss_cfg.weights），当前帧 + 相邻帧各一份。
  • 显式关闭的：LSS 深度分布的辅助深度损失 depth_loss_weights=[0.0]——深度监督完全交给渲染链路，不做双份。
  • GT 细节：像素值 ÷255 归一；深度 GT 取 LiDAR 投影，sensor_depth_truncation=0.1 截断过近的无效返回，无投影像素记 −1 不计入损失。
  • 训练配置：AdamW lr=4e-4，12 epochs，fp16 混合精度，每 GPU batch=1——4 帧×6 目的渲染链显存开销大（这是它吞吐的瓶颈，也是 §5 局限的来源）。

§5Conclusion

5.1这篇工作证明了什么

  • 掩码建模可以同时开在空间和时间两个域，且两者互补：一个补几何、一个补动态。
  • ego-motion 对齐下的跨帧渲染一致性是免标注的时序监督源，不需要光流伪标签。
  • 多视角视频预训练的收益随窗口长度增长且未见顶，给"更长时间上下文"路线提供了实证。

5.2局限

  • 渲染链显存开销大：每 GPU batch 只有 1，4 帧×6 目的 ray 采样+MLP 前向限制了训练吞吐（代码注释里 fp16 全开）。
  • 时序对齐依赖 ego-motion 标定质量，剧烈颠簸或标定漂移会污染相邻帧监督。
  • 窗口消融在 ResNet-50、450×800 分辨率下做， ConvNeXt-S 全分辨率下 5 帧是否同样未饱和论文未验证。

5.3后续方向

  • 更长时序窗口：论文自己指出显存允许时继续加帧；这与 Tesla FSD v14 把上下文拉到 ~30s 的方向一致。
  • 渲染器升级：NeuS 逐 ray 积分慢，换 3D Gaussian Splatting 类渲染头是显然的效率升级路径。
  • 与 UniPAD 的 LiDAR 渲染支线统一成多模态版本，代码库（UVTR）本身就留了 use_lidar 接口。
