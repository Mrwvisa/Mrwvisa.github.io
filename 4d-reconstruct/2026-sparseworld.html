SparseWorld：稀疏动态 query 驱动的 4D 占用世界模型

SparseWorld: A Flexible, Adaptive, and Efficient 4D Occupancy World Model Powered by Sparse and Dynamic Queries · arXiv 2510.17482 · github.com/MSunDYY/SparseWorld · Occ3D-nuScenes · AAAI 2026

§1Motivation

问题是什么、难在哪、别人怎么解、SparseWorld 怎么解。

占用世界模型大多建立在静态固定的嵌入或网格上：要么先把每帧占用编码成嵌入再解码预测（感知预测解耦，梯度断、细节丢），要么在网格特征上做"原地分类"式预测（end-to-end 通了，但网格是静态的，和真实场景的连续动态天然错位）。SparseWorld 的答案是换表征载体：概括一句话：用稀疏动态 query 替代静态网格的自适应 4D 占用世界模型，回归式预测对齐连续动态，感知/预测/规划三任务 SOTA。query 是稀疏的所以快，是动态的所以能跟着场景演化走，是可学习且被自车状态调制的所以感知范围能自适应伸缩。

1.1面临的问题和难点

解耦范式的梯度断裂

感知-预测解耦类方法（OccWorld 式）：先逐帧 tokenize 占用，再用未来向的解码器融合——梯度回不到感知，反复编解码还丢细粒度信息。

原地分类与连续动态错位

网格方法在每个格子上做分类式预测——格子是静态的、离散的，物体运动却是连续的；预测质量受限于表征与世界的这种错位。

1.2别人是怎么解决的

路线代表工作做法 & 麻烦
解耦式占用世界模型OccWorld / OccLLaMA占用 tokenize + 自回归预测；感知预测分离，端到端优化受阻。
网格特征端到端PreWorld 等感知特征直接做逐格预测，梯度通了；但静态网格 + 原地分类，FPS 只有 1.0，mIoU 9.06。
稠密 query 感知DETR3D / StreamPETR 系证明了 query 载体的效率；但没人把动态 query 用于 4D 占用世界模型。

1.3SparseWorld 是怎么解决的

三个模块各对应一个卖点。Range-Adaptive Perception：一组可学习 query 被自车状态（速度、加速度等）调制，再与多视角时序特征做时空关联——感知范围随驾驶状态自适应伸缩（高速看得远、低速看得细），这是"灵活"。State-Conditioned Forecasting：未来预测不做逐格分类，而是让动态 query 直接回归未来状态，query 的连续运动与 4D 场景的连续性对齐，这是"自适应"。Temporal-Aware Self-Scheduling：按时间感知地调度各监督源的训练节奏，收敛平稳、训练省，这是"高效"。规划侧接 AD-MLP 头输出轨迹，全链路一套 query 表征。

1.4优点和效果

  • 又快又准：4D 预测 mIoU 13.20（第二名 9.55），FPS 8.0（对手 1.0）——不是拿算力换精度，是拿表征换的。
  • 长视野不塌：预测 3s 时 mIoU 仍 11.51（PreWorld 7.15），动态 query 的连续回归在长视野优势放大。
  • 规划同样能打：带自车状态的 SparseWorld† L2 平均 0.27m、碰撞率 0.29%，全面好于 UniAD 与 PreWorld†。
  • 效果预告见 §4：三张表的完整对比。

§2Architecture

先看总图（模块级）。官方仓库含 configs/sparseworld 与 AD-MLP 规划头，具体维度以论文叙述为准。

2.1Overall Pipeline

图 2-1 · SparseWorld 总流程：动态 query 感知 → 回归式 4D 预测 → 占用输出与 AD-MLP 规划；自调度训练策略贯穿。
输入 感知 预测/训练策略 输出 监督流
  • 感知链路：多视角图像序列 → 可学习 query 被 ego 状态调制后，与图像时序特征做时空关联，得到携带场景状态的动态 query——感知输出不是网格，是一组会动的锚。
  • 预测链路：State-Conditioned Forecasting 让 query 直接回归未来时刻的状态，1s/2s/3s 逐视野输出占用；分类式"这个格子是什么"变成回归式"这个 query 到哪了"。
  • 规划链路：动态 query 状态接 AD-MLP 头出轨迹，感知、预测、规划共享同一套表征——端到端梯度无阻。
  • 训练链路：Temporal-Aware Self-Scheduling 按时间维度调度监督源的介入节奏，多任务训练平稳收敛。

§2.2Range-Adaptive Perception

  • ego 状态调制是"灵活"的来源：query 集合不是固定的感知预算——自车开得快，query 关注的感知范围向外扩；低速拥堵时收缩加密近场。状态条件让一套 query 适配不同驾驶情境。
  • 时空关联：query 与多视角、多帧特征做关联聚合，历史信息在 query 载体上延续（不回炉编解码），细粒度信息保得住。

§2.3State-Conditioned Forecasting

  • 回归替代原地分类：网格法在固定格子上做分类，物体连续运动和离散格子天然错位；动态 query 直接回归未来位置/状态——表征跟着世界动，这是"自适应"的来源。
  • 长视野收益放大：预测 1s 时 mIoU 领先 2.66，3s 时领先 4.36（vs PreWorld+预训练）——视野越长，连续回归的优势越大。
  • 条件即动作接口：自车状态作为预测条件，天然支持"换状态看不同未来"的可控生成。

§2.4Self-Scheduling Training

  • 按时间感知调度：感知、预测、规划多个监督源不是同时全开，而是按时间维度的调度策略渐进介入——避免多任务互相拖拽，训练平稳。
  • 效率是结构性的：稀疏 query 让推理 FPS 达 8.0（基线 1.0）——8 倍速度不是剪枝剪出来的，是表征载体本身便宜。
  • 训练足迹：4×A100、总 batch 8，训练与推理同架构（无 teacher/多阶段）。

§3Loss

L = Lperc(占用感知) + Lfcst(未来 query 回归) + Lplan(轨迹)
三路监督分别落在感知占用、未来时刻的 query 回归目标与规划轨迹上，由 Temporal-Aware Self-Scheduling 调度介入节奏；GT 来自 Occ3D-nuScenes 语义占用与轨迹。具体权重以论文实验节与官方 config 为准。
  • 监督需要 3D 占用标注（Aux. Sup. = 3D Occ）——与 GaussianWorld 类似的监督设定，非免标注路线。
  • 预测损失作用在 query 的回归目标上而不是逐格分类——损失形式与表征载体一致，这是它能拿到长视野收益的结构原因。

§5Conclusion

5.1这篇工作证明了什么

  • query 载体可以从检测任务搬进 4D 占用世界模型，且三任务（感知/预测/规划）一把抓。
  • 回归式预测与连续动态的对齐，比分类式原地预测更适合 4D 世界，视野越长越明显。
  • 表征选对了，效率与精度可以同时拿（8 FPS + SOTA）。

5.2局限

  • 依赖 3D 占用标注训练（非自监督），规模化受标注成本约束。
  • 动态 query 的数量与初始化如何影响远场感知，论文消融有限。
  • 官方代码仓在论文发表时仍在补充中，复现需盯仓库更新。

5.3后续方向

  • 把 ego 状态条件扩展为完整动作条件（速度/转角/轨迹），对齐 Drive-OccWorld 的可控生成接口。
  • query 载体 + 自监督监督源（渲染式预训练）组合——表征便宜与监督便宜叠加。
  • 与 Gaussian 载体（GaussianWorld）、隐式场（DIO）做系统性同台对比——三种稀疏表征的家族内战。
