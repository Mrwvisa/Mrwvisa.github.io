DUSt3R：把几何 3D 视觉做成一个回归网络

DUSt3R: Geometric 3D Vision Made Easy · arXiv 2312.14132 · github.com/naver/dust3r · 8 数据集 / 8.5M 图对 · CVPR 2024

§0速览卡

核心解读

先看一个想法：照片里每个像素，都对应场景里一个真实的 3D 点。如果能给每个像素找到它正确的 3D 坐标，一张照片就变成一片点云。DUSt3R 训练一个网络做这件事：输入两张图，给每个像素回归一个 3D 坐标（点图）。关键在监督信号：第二张图点图的答案（GT），是把它的 3D 点用相机位姿变换到第一张图的坐标系里做出来的。网络朝这个目标学，两张点图自然写在同一套坐标系里，同一个物理点落到同一个位置，预测得越准，落得越齐。像素对应从这套坐标系里直接出来，不需要专门的匹配算法。深度、位姿、内参、对应关系、场景重建，都从这一个回归目标里长出来。

  • 目标：深度、位姿、对应关系、三维重建，传统流程里是分开做的好几件事，每件都有自己的流水线；DUSt3R 把它们合成一件：输入两张图，一次前馈，给每个像素回归一个 3D 坐标（点图），两张图的点图写在同一套坐标系里。做法是直接回归：不检测特征、不做匹配、不解几何方程，网络自己从像素学出 3D 坐标。两支解码器逐层交换信息，也是这套格式的要求：第二张图的点图要写进第一张图的坐标系，它就必须参考第一张图的信息（各模块怎么连，见图 0-1）。
    图 0-1 · DUSt3R 核心机制：两图一次前馈，输出同一坐标系下的两张点图；对应关系 = 3D 坐标重合。shape 取自官方 512 checkpoint 配置。
  • 训练：
    • 输入：图像 I¹、I²，长边缩到 512（训练时随机长宽比，如 512×384，见 §3.2）；训练集 8 个数据集共 850 万对。
    • 输出：预测点图 X¹,¹（图像 1 每个像素的 3D 点）和 X²,¹（图像 2 的点，也写在图像 1 的相机系），各 [512,512,3]；外加每像素置信度 C，各 [512,512]。
    • GT：不用人工标注，来自数据集自带的深度图和位姿：深度图反投影成 3D 点，再变换到图像 1 的相机系，得到两条监督信号 X1,1（图像 1 的点）和 X2,1（图像 2 的点，也写在图像 1 系）。记号说明：X 加横杠表示真值（答案），用来和预测 X 区分——X1,1 就是 X¹,¹ 的答案；上标两个数字分别是「哪张图的点」和「写在谁的坐标系里」。没有深度值的像素用 mask 剔除。
    • Loss：逐像素配对来算——X¹,¹ 对 X1,1、X²,¹ 对 X2,1，各算欧氏距离、乘置信度求和，再补一项把置信度校准到合理大小。全程只此一项：没有匹配损失、位姿损失、内参损失。公式和每个变量的含义：
      L = Σ C·ℓ − α·log C，  C = 1 + exp(c)，  α = 0.2
      公式里每个符号的含义：
      X：网络输出的预测点图（X¹,¹、X²,¹，每个像素一个 3D 坐标，各 [512,512,3]）
      X：真值点图，由数据集自带的深度图 + 位姿构造（X1,1、X2,1）
      ℓ：预测点和真值点之间的距离，即 ‖X − X‖（欧氏距离；两侧先按平均尺度归一，只管形状、不管绝对大小）
      c、C：置信度——c 是网络输出的原始参数，C = 1 + exp(c) 是损失里加权用的置信度；拿不准的点自动调小，但降不到零
      α：平衡系数（官方 0.2）
      完整推导见 §3。
    训练从 CroCo v2 的预训练权重出发，那套预训练学的就是「两幅图里哪些内容是一回事」，正好给跨视图对应打底。
    图 0-2 · 训练流程：两张图过网络得到预测点图；GT 由深度图 + 位姿构造；逐点距离回传更新权重（图内只放符号，公式与变量解释见训练条）。shape 为官方 512 配置，输入长边 512、训练时随机长宽比。
  • 推理：
    • 输入：图像 I¹、I²，各 [3,512,512]；不需要任何相机参数。
    • 输出：一次前馈（约 40ms）得到点图 X¹,¹、X²,¹（各 [512,512,3]）和置信度 C（[512,512]）；配上颜色就是彩色点云（论文图 3）。从它直接读出三样东西：
      • 深度：取 Z 通道，得到深度图 [512,512]。
      • 位姿：由点图解出——两张点图都写在图像 1 的坐标系里，图像 2 每个像素的 3D 位置已知；把这些 3D 点（X²,¹）、配上它们在图像 2 里的像素坐标和相机内参，就是一个标准 PnP 问题（已知 3D 点和对应像点，反求相机位置），解出相机 2 相对相机 1 的旋转和平移。内参未知也能一起估，精度会降（见 §4）。
      • 对应关系：坐标重合的像素即对应，不需要匹配网络。
    • 后处理：多图重建时，各对分别前馈后做一次全局对齐（调每张图的深度、位姿、焦距，让重叠区域尽量对齐，几百步、秒级），拼成整个场景。
    图 0-3 · 推理流程：两张图一次前馈得到两张点图，深度 / 位姿 / 对应各有读法；多图重建做一次全局对齐。shape 为官方 512 配置。
  • 效果：
    • 定性：把点图渲染出来，就是照片级的彩色重建（论文图 3）。
    • 定量：所有评测都是零样本跑出来的——多视图位姿超过专门训练的方法（CO3D 66.5 → 76.7）；单目深度与全监督打平（NYUv2 6.50）；多视图重建从 COLMAP 的几分钟缩到 0.13 秒（数字见 §4）。
  • 结论：换一个好的输出表示，比改进流水线里的模块更管用：点图一个张量装下所有几何输出，特征提取、匹配、几何求解一整族传统模块可以直接省掉，一个回归网络就够。

QA 档案

Q：深度图、位姿、像素对应，是从点图里直接读出来的吗？
A：分开看。深度是读的：参考视图的点图里，Z 坐标就是深度，不用计算。位姿是算的：拿 X²,¹ 的 3D 点、配上图像 2 的像素解一次 PnP，得到两张图之间的旋转和平移。对应关系是几何必然，同一个物理点在共享坐标系里坐标必然重合；但要列出对应点仍要做一次坐标查找，不需要额外训练匹配网络。
Q：两张点图的坐标为什么会重合？网络里有一个「把两片点拼起来」的目标吗？
A：没有。训练里只有一件事：每个像素的预测去逼近 GT。「重合」来自 GT 的做法：第二张图点图的 GT，本身就是用相机位姿把它的 3D 点变换进第一张图的坐标系里构造的，所以同一个物理点的坐标在两个点图里就是同一个点。网络学得越准，输出的重合度就越高。
Q：推理时，图像之间有「点云融合」这一步吗？最终输出的点云是什么样？
A：分两种。单对推理：没有融合操作——一次前馈直接输出两张点图（X¹,¹、X²,¹），两张本来就写在同一个坐标系（图像 1 相机系）里；重叠区同一个物理点由两侧像素各出一个点，坐标相互重合但不合并、不去重，直接叠加渲染就是论文图 3 的彩色点云。多图推理：网络仍然只两两前馈；跨图的统一靠 §2.4 全局对齐（优化）完成——每张图的深度图是共享变量，和世界系位姿、焦距一起求解，解完每张图导出「每像素一个世界系 3D 点」，拼起来才是最终场景点云（每个像素恰好贡献一个点）。所以跨图一致性是优化算出来的，不是网络输出自带的。重叠区的「重复点」不去重：两片坐标本来就该重合，叠在一起看起来就是一片；多图时同一张图被多个图对重复预测的深度，被全局对齐合并成一份（这是唯一的合并操作），而跨图像的重复点不做去重。要「干净」的单层点云得自己做后处理（体素下采样 / TSDF 融合之类），DUSt3R 不含这一步；整个流水线到点云为止，不产出 mesh / 表面——点云本身就是它定义的「重建完成」。
Q：为什么第二张图输出的是 X²,¹（写在图像 1 系），而不是 X²,²（写在它自己的系）？为什么这两个输出就等于重建好了？
A：因为各写各的系，两片云彼此不搭界——要拼成场景得先匹配、再求位姿、再配准，等于把传统流水线请回来。DUSt3R 把第二张图直接写进图像 1 的坐标系，于是：对应关系免费（坐标重合即对应）、重建免费（两片直接叠合就是同一场景）、两支解码器的信息交换也从「可选」变成「必须」。监督可行性也没问题：X²,¹ 的 GT 用图像 2 的深度 + 相对位姿变换就能构造。X²,² 并非不存在——交换顺序再跑一次（I², I¹）第一张输出就是它，位姿评估的 PnP 解码会用到；两种写法信息等价，区别只在「拼接和对应是不是提前免费化」。
Q：Loss 里的 C = 1 + exp(c) 是什么设计？置信度为什么不直接取 0~1？
A：C 的物理含义是「这个像素自报的测量精度」（误差尺度的倒数）：网络在预测 3D 坐标之外，为每个像素报一个不确定度 σ，C ≈ 1/σ——C 大 = 自认预测精密、误差范围窄。这个损失式不是拍的，它是「每像素自学噪声尺度」的负对数似然：C·ℓ 是标准化残差（错得多离谱 ÷ 该像素自己的尺度），−α·log C 是「宣称精确」要交的税（分布归一化项）；平衡点 C* = α/ℓ 的含义就是校准——自报的精度必须和真实误差吻合，只有误差小的地方才允许报高精度。它不是概率、也不需要 0~1，取值范围 (1, +∞)：上不封顶（真准就可以极准），下界 1 等于「误差尺度最多 1」——不许把不确定度开到无穷大（那等于弃权，训练里这个像素就不再产生梯度）。c 是回归头自由输出的任意实数（无激活），exp 恒正、加 1 后下界就是 1（c=−10 → C≈1.00005，c=0 → C=2，c=2.2 → C=10）。C 没有任何监督信号，整个分配由损失自身平衡。设计动机：让学习信号自动分给「学得动」的像素——难像素（天空、外推区）降权但不许归零（论文的 forcing the network to extrapolate），且 C 本身在下游有用（图对过滤、全局对齐加权）。
Q：天空像素、只在单张图里可见的点、两图都可见的点——训练时各自经历什么？损失怎么刻画它们？
A：三类走同一个公式，没有「如果你是天空就怎样」的规则——只是它们的 ℓ（错量）天然分层，平衡点 C* = α/ℓ（0.2/ℓ）自动给出不同待遇：①两图都可见的重叠点：两张图各有一个像素、各有一份 GT，且两份 GT 坐标是同一个点（构造保证），互相强化，ℓ 小 → C* 大（如 ℓ=0.05 → C≈4），权重高、梯度主要从这里来；②只在单张图可见的点：只有一侧监督，靠上下文外推，ℓ 偏大 → C* 想低于 1、被下界顶到 1，按原价计入（逼外推的落点）；③天空：真实数据集多半没有 GT（深度传感器测不到）→ valid_mask 剔除、不参与训练，推理时拿到的 C 是从相似区域学来的、偏低；若有 GT，ℓ 很大 → 同样顶在 C=1。注意「置信度低」= C 贴着 1（保底一份），不是 0。学得好的直接证据是 C 场的结构：重叠/纹理区明显 >1、天空/外推区贴着 1，等于一张「我知道哪里我知道」的自评图；若没学好，ℓ 到处大 → C 全场贴 1、无区分度。且这张 C 图下游真能用（图对过滤、对齐加权），说明它是有效信息而非装饰。
Q：难像素的权重被保底在 1，为什么不让它接近 0？这样不会拖累训练吗？
A：这是故意的取舍，而且和另一套机制配合使用。关键前提：真实数据集里天空通常没有 GT（深度传感器/重建测不到）→ valid_mask 直接剔除、不参与训练；所以保底 1 罚的不是「真天空」，而是「有 GT 但难」的像素（远小物体、玻璃、暗光、单图覆盖区）——那些恰恰是网络必须努力学的。如果权重允许趋 0，打开的不是「诚实地承认测不准」，而是「凡是我现在学不好的地方都宣布弃权」的捷径——所有暂时学不好的区域会被一起打包扔掉，永远不再进步。保底 1 的含义：可以报「我没把握」（C 贴着 1），但错量照原价计入，逼网络在没证据处也基于上下文外推（forcing the network to extrapolate），重建才不会到处是洞。代价确实存在（难像素占用一部分学习容量），论文选择宁可贵一点也不让网络学会找借口。整套设计是两层配合：没答案的靠数据集层面 mask 掉，有答案但难的靠损失层面保底 1 硬学——惩罚的是「偷懒」，不是「承认不确定」。注意保底 1 不是永久惩罚：难像素的 ℓ 随训练变小、一旦小于 α=0.2，平衡点 C* = α/ℓ 自动升过 1，权重自动变大——等于「保留学习桌位、学好了自动升舱」，给「从难到易」留了正常上升通道。
Q：既然权重下界焊死在 1、不许弃权，那 confidence 这个维度是不是没什么意义？
A：一半对一半错，分三个角色看。①「丢弃垃圾数据」的角色确实被阉了：经典不确定度加权里低权重≈变相忽略，这里不允许——如果只把 C 当「要不要听这个像素」的开关，它确实是废的。②「训练注意力分配」的角色真在起作用：以每个像素自身的难度为单位归一化——好学的像素 ×10 说话、难的 ×1 保底，避免大面积难区按绝对误差主导梯度。③「产出可靠性图」的角色下游真消费：全局对齐给点加权、图对过滤判重叠质量都用它——这只需要 C 的排序有效（难=1、易>1），不需要趋 0，排序就是信息。诚实补充：论文没有「去掉置信度」的消融，「有它比没有强多少」没有直接数字；但②③有据可查，「完全没意义」过了。背景：C·ℓ − α·log C 是学不确定度的标准形态（Kendall & Gal 一类），下界恰恰是为了让它别沦为「丢弃开关」——作者要的是分配 + 校准 + 下游可用。
Q：推理时怎么用 C「过滤」？α 也参与过滤吗？
A：全部是真码，分四层：①每张图的置信度 = 逐对预测的逐像素 max（base_opt.py：图像 i 参与的每一对里取该像素 C 的最大值）——不是平均；②像素级硬筛：get_masks() 就是一行布尔「C > min_conf_thr」，默认阈值 3（demo 滑条 1~20、默认 3.0），点云导出/可视化按它剔除；筛之前还有降级步骤 clean_pointcloud——跨视图对账，穿模/不一致的点 C 夹到 0，mask_sky 时天空也置 0；③图对级打分：edge_conf = mean(Cᵢ) × mean(Cⱼ)（commons.py，乘积），用于 MST 初始化排序——分最高的对先当骨架边，新图沿边做置信度加权的刚体配准（每个点用自己 C 当最小二乘权重）；④优化级加权（非删）：对齐权重 = log(C)（conf='log'）——log(1)=0，所以难像素在优化里的权重恰好归零，训练侧「下界 1」在推理侧完全不影响筛除效果。α 不参与推理（它只活在训练损失里，痕迹只剩 C 学会的刻度）。

§1Motivation

问题是什么、难在哪、别人怎么解、DUSt3R 怎么解。

从一组照片恢复 3D 场景和相机参数，传统上是一条手工流水线：提特征、匹配、几何验证、增量重建、Bundle Adjustment、稠密化，每一步都有自己独立的假设和超参。DUSt3R 的观察是：这些任务各自的输出物——深度、位姿、内参、像素对应、稠密重建——其实是同一个底层量（场景的 3D 几何）在不同投影下的切片，那就不必拆开逐个求解，让一个网络直接回归这个底层量。表示上它选了一个极简的载体：每个像素一个 3D 点坐标，即点图；两张图一起进网络，输出写在同一坐标系里的两张点图。整套方法概括起来就是：两张图一次前馈直接回归公共坐标系下的像素级 3D 点图，深度、位姿、内参、对应关系全部变成这一个回归目标的副产品。

1.1面临的问题和难点

流水线长，工程重

经典 SfM/MVS 把「照片 → 3D」拆成六七个独立步骤，每步只优化自己的局部目标，误差逐步累积；窄基距、弱纹理、重复纹理随时让某一步失效，而失效后很难定位是哪一步坏了。

结果是这套体系更像几何专家系统：成熟、精确，但换一个场景类型就要重新调参，没有从数据里学先验的机制。

学习方法各自为战

深度估计一个网络，相对位姿一个网络，特征匹配又一个网络——表示互不通用（深度图、位姿矩阵、描述子各是各），学到的几何先验无法共享，换任务就得换模型重训。

端到端位姿回归方法在特定数据集上能刷高，但跨域衰减快，而且只输出位姿这一个量，深度和重建还是要另找工具。

1.2别人是怎么解决的

路线代表工作做法 & 痛点
手工几何流水线 COLMAP / OpenMVS 特征→匹配→RANSAC→增量 SfM→BA→MVS。精确但脆：每步独立优化、误差累积，窄基距弱纹理易崩，对账要靠经验；速度也慢，一组图几十分钟到小时级。
单目深度网络 DPT-BEiT / NeWCRFs 单图回归深度，大数据训练后跨域不错。但单目深度本质 ill-posed，尺度不定；而且只解决深度这一件事，位姿、对应、重建还得另配工具。
端到端位姿回归 RelPose / PosReg / PoseDiffusion 直接从多张图回归相对位姿。任务特化严重：输出只有位姿；PoseDiffusion 靠扩散采样，推理慢，在 CO3Dv2 之外的数据集上掉得明显（论文表 2 右）。
可微 SfM / 学习式 MVS Vis-MVSNet / DeepV2D 把流水线的某个环节换成网络端到端训练。普遍需要 GT 相机位姿当输入或初始化，适用面窄，仍然不是「一个模型管所有几何任务」。

1.3DUSt3R 是怎么解决的

核心思想：选一个信息密度足够高的输出表示，让一个回归目标覆盖所有几何任务。点图 X ∈ ℝW×H×3 给每个像素一个 3D 点坐标：深度是 Z 通道，位姿是两张点图之间的刚体变换，内参隐含在像素与射线的对应里，像素对应就是坐标重合：传统流水线要分开求的这些东西，全在点图这一张里。

网络定义也随之变得干净：两张图 I¹、I² 进一个双分支 Transformer，输出两张点图 X1,1、X2,1 和对应的置信度图，关键是两张点图都写在图像 1 的相机坐标系里。GT 完全由现成数据构造（深度图加相机位姿做一次坐标变换），所以能在 8 个数据集的 850 万图对上全监督训练，不需要任何新标注。

架构上刻意不加几何约束：没有相机模型层、没有对极约束、没有三角化模块，几何先验完全从数据里学：训练集里的点图本来就是几何一致的，网络只需把这份一致性学会。换来的是网络完全通用，可以直接用 CroCo 跨视图补全的预训练权重初始化——这是它收敛又快又好的隐藏前提。

1.4优点和效果

  • 一个模型同时服务一堆任务：多视图位姿、单目与多视图深度、视觉定位、点云配准、MVS 稠密重建，全部零样本直接推理，不需要按任务微调（论文表 1~4）。
  • 对应关系不用专门学：两张点图天然在同一个坐标系里，重叠区坐标重合就是像素对应，全程没有匹配损失和对应标签——特征提取、匹配、RANSAC 这一族模块整体消失。
  • 快：逐对前馈约 40ms（H100），多图融合的全局对齐是 3D 空间的最小二乘，秒级收敛；对照 COLMAP 一组图分钟到小时级的重建。
  • 零样本成绩硬：10 帧多视图位姿 CO3Dv2 mAA 76.7（PoseDiffusion 66.5）、RealEstate10K 67.7（48.0）；多视图深度五个数据集平均 rel 4.73，超过带 GT 位姿的专用方法（论文表 3）。
  • 分辨率和预训练都生效：224 升到 512、去掉 CroCo 初始化对照明显，NYUv2 零样本 rel 从 14.51（无 CroCo）降到 10.28（224）再到 6.50（512），见 §4 消融。

先看前馈总图（模块级，每个模块标真实输入输出 shape），细节留给三个子模块小节。

2.1Overall Pipeline

图 2-1 · AsymmetricCroCo3DStereo 前馈总流程：共享编码器 + 层间互通的双解码器 + 双 DPT 头，输出同一坐标系下的两张点图。shape 取自官方 512 checkpoint（img_size 512、patch 16）。
输入 编码器 / 解码器 / 回归头 输出 数据流 监督 / 训练细节
  • 输入侧只有 resize，没有标定要求：长边缩到 512、保持长宽比；训练时每 batch 随机长宽比（16:9、4:3 等，靠随机裁剪实现），所以推理时网络对各种画幅都熟；竖图由 landscape 包装器先转置再进网络。
  • 编码器是真正共享的 Siamese：代码里 I¹、I² 直接沿 batch 维拼接后过同一个 ViT-Large 再切开（_encode_image_pairs），两图各自得到 1024 个 token、1024 维。
  • 解码器是两套权重：dec_blocks2 是 dec_blocks 的深拷贝，加载 CroCo 预训练权重时同源复制、训练中各自更新——「双胞胎」而不是共享。每个块先做本视图 self-attn，再 cross-attn 查询对方分支的全部 token，最后 MLP。
  • DPT 回归头从解码器第 0/6/9/12 层钩出多尺度 token，refinenet 逐级融合后输出 4 通道：点图 3 维 + 置信度 1 维。深度分量过 exp 激活，天然保证正视深度。
  • 「非对称」来自输出的定义：head1 给 X1,1（图像 1 自己的点，图像 1 系），head2 给 X2,1（图像 2 的点，也在图像 1 系，代码键名 pts3d_in_other_view）。
  • 监督只挂在输出端：GT 点图由深度图加位姿做一次坐标变换构造，损失是置信度加权的欧氏距离（§3）。训练时同一对图两种顺序都喂，网络不会偏科「谁当锚点」；已对称的 batch 编码器只算一半，省一半算力。
  • 多图场景就是两两重复这个前馈（或先检索挑边），再做一次全局对齐（§2.4），不存在第三种网络调用。

§2.2AsymmetricCroCo3DStereo

网络主体直接继承 CroCo：编码器、解码器、双流互通的骨架都是 CroCo 的，DUSt3R 做的事是把「跨视图补全 patch」换成「回归点图」，再补两个输出头。下面按一次前馈的顺序过一遍内部步骤：

  • 「非对称」指输出的定义方式，不是结构：两条支路结构对称，但 head2 的输出写在 view1 的坐标系里（pts3d_in_other_view），一支「自我定位」、一支「换系投影」，任务并不对称。
  • 解码器两套权重的来历：dec_blocks2 = deepcopy(dec_blocks)，初始化同一套随机权重；加载 CroCo 预训练 checkpoint 时，若没有 dec_blocks2 前缀的键，就把 dec_blocks 的权重复制一份过去（load_state_dict 兼容逻辑）。之后训练中两支各自更新，逐渐分工。
  • 交叉注意力的接线就一行：blk1(final[::+1], pos1, pos2)、blk2(final[::-1], pos2, pos1)——参数顺序就是「谁的 token 查询谁」，每个解码块执行 self-attn、cross-attn、MLP 三段。
  • 位置编码用 RoPE（相对位置），patch 大小 16；ManyAR_PatchEmbed 支持任意长宽比：图像 padding 到 patch 整数倍，true_shape 记录有效区域，注意力只算有效 token。
  • 竖图有个省事的处理：landscape 包装器把竖图转成横图进网络（权重只在横向分辨率上训练过），输出点图再转置回来，竖图也能直接跑。
  • 给下游留了 freeze 开关（none / mask / encoder），DUSt3R 本体训练用 none 全量更新；后续工作（如 MASt3R）就是冻住 encoder 在这上面加匹配头。
  • 对称化训练的算力账：每个 batch 同时含 (I¹,I²) 和 (I²,I¹)，is_symmetrized 检测到后编码器只算一半再 interleave 回来——两份监督、一份编码开销。

§2.3DPT Regression Head

解码器 token 是 1024 个离散格子，点图却是 512×512 的稠密场，中间靠 DPT 头桥接：从解码器不同深度钩 4 层 token，多尺度融合后逐像素回归。发布模型还有个演进故事——224 阶段用纯线性头，512 阶段才换 DPT：

  • 钩哪几层是算出来的：hooks_idx = [0, l2·2/4, l2·3/4, l2]，l2 = 解码器深度 12，即第 0/6/9/12 层；四层的 token 维度分别是 [1024, 768, 768, 768]（第 0 层是投影后的编码器 token）。
  • 融合网络是 DPT 标准件：每层先 act_postprocess 升采样到统一空间，layer_rn 投到 256 维，refinenet 从第 4 层往下逐级融合（4→3→2→1），最后 1×1 卷积出 4 通道。feature_dim=256，last_dim=128。
  • CroCo 原版 DPT 里有一组重复权重（act_1~4_postprocess 与 encoder 侧重复），DUSt3R 直接删掉，只留 decoder 侧的一份。
  • 头类型分两档：head_type='linear' 对最后一层 token 直接线性回归（224 低分辨率阶段，便宜）；head_type='dpt' 多尺度融合（512 阶段，也是发布权重 DUSt3R_ViTLarge_BaseDecoder_512_dpt 的配置）。训练课程因此是 224-linear → 512-linear → 512-dpt 三段接力。
  • 输出后处理两行定生死：深度分量 z = exp(x)（depth_mode），保证正视深度；置信度 C = 1 + exp(c)（conf_mode），保证 C > 1——为 §3 里「逼网络外推」的损失设计留好接口。

§2.4Global Alignment

网络一次只吃两张图，N 张图的场景怎么拼？DUSt3R 的答案是把多图融合也做成一个干净的最小二乘：每对图各跑一次前馈拿到局部点图，再在 3D 空间里把它们对齐到一个世界坐标系。整个过程没有任何网络参与：

  • 选边两种策略：小图组直接完全图（10 帧就是 45 对，每对约 40ms）；大图组先用现成图像检索挑近邻，或者全跑一遍用平均置信度过滤低重叠对。
  • 优化变量全在相机侧：每张图一份 log 深度图（可微的正深度）、一个 7 自由度位姿、一个 log 焦距（可选主点），外加每个图对一个成对变换和尺度因子。网络输出全程冻结，只当观测用。
  • 目标函数就是置信度加权的 3D 对齐距离：‖χ − σₑ·Pₑ·X‖，χ 是世界系点图、Pₑ 和 σₑ 是图对的刚体变换与尺度（代码 PointCloudOptimizer.forward，即论文 Eq.5 的落地）。
  • 初始化不用瞎猜：init='mst' 按置信度建最小生成树，逐边做 PnP（10 次迭代）把位姿先摆到大致位置，再做全局迭代优化。
  • 和传统 BA 的本质区别：BA 最小化 2D 重投影误差，非线性强、要 LM 或稀疏求解器；这里最小化 3D 对齐误差，普通梯度下降几百步收敛，一张普通 GPU 秒级出结果。约束 Πσₑ=1 防止尺度全零的平凡解。
  • 副产品是全套相机参数：把 χ 参数化成针孔模型（深度×K⁻¹×位姿），优化完直接读出所有图的位姿、焦距和深度图；已知量也可以预设（preset_pose / preset_focal），变成半约束重建。
  • 一张图重复出现在多个图对里时，它的深度图是共享参数——不同邻居的观测在约束同一份深度，这是「多图一致性」进来的地方。

§3Loss

3.1一个损失练出一切

ℓregr(v,i) = ‖ Xv,1i / z − Xv,1i / z ‖,    z = norm(X1,1, X2,1)
论文 Eq.2/3，v ∈ {1,2}。逐像素欧氏距离（代码 L21Loss），z 是两张点图所有有效点到原点的平均距离（norm_mode='avg_dis'），预测和 GT 各自归一后再比。SfM 重建的数据尺度本来就任意，这一步把尺度歧义从损失里拿掉——网络只对「形状」负责，不对绝对尺度负责。
L = Σv∈{1,2} Σi∈𝒟v [ Civ,1 · ℓregr(v,i) − α · log Civ,1 ],    C = 1 + exp(c)
论文 Eq.4，α = 0.2（官方训练命令）。置信度 C 没有任何监督信号：对 C 求导置零，平衡点是 C* ≈ α/ℓ——每个像素的置信度自动收敛到预测难度的倒数。C > 1 的下界是故意的：难像素（天空、单视图覆盖的外推区）的权重最多降到 ℓ 本身，降不到零，网络被迫在难处也给出外推，这就是论文说的「forcing the network to extrapolate」。
图 3-1 · 损失链路：GT 构造 → 尺度归一 → 欧氏距离 → 置信度加权，反向传播覆盖整个网络。
  • GT 不用人工标注：深度图按Xi,j = K⁻¹[iD, jD, D]ᵀ 反投影成点图，再统一变换到图像 1 相机系（代码 inv(gt1['camera_pose']) 一行）；valid_mask 剔除无深度像素。合成数据、SfM 重建、深度传感器三种来源的 GT 都走同一条路。
  • 整个训练只有这一个损失：没有匹配损失、没有位姿损失、没有内参损失、没有正则项。对应关系、相机参数全部是这个回归目标的隐式产物。
  • 代码里的 ScaleInv / ShiftInv / ScaleShiftInv 三个变体训练时都没用——它们是测试准则（Regr3D_ScaleShiftInv(L21, gt_scale=True)，评估时把预测缩放到 GT 尺度再算距离）。
  • 对称化在损失这一层生效：symmetrize_batch 让每个 batch 同时含两种顺序，X1,1 和 X2,1 的角色互换着练，网络对「谁当锚点」不敏感。
  • 训练数据 8 个数据集共 8.5M 图对，每 epoch 从各数据集等量采样抹平规模差异；配比见下表。

§5Conclusion

5.1这篇论文证明了什么

  • 「通用架构 + 大数据回归」可以整体替代手工几何流水线：一个不带任何几何约束层的网络，在 8.5M 图对上只练一个回归损失，就把位姿、深度、重建零样本全做了，而且多数指标超过各任务的专用模型——「每个几何任务一个定制网络」的默认设定被打破。
  • 表示选择是最高杠杆的创新：一张点图就把全部几何输出装下了，特征提取、匹配、RANSAC、三角化、BA 一整族模块随之消失。改表示比改模块省事，效果还更通用。
  • 对应关系可以是几何副产品：不需要匹配监督，把两张点图钉在同一个坐标系里，坐标重合即对应。它能成立靠三件配套的事：CroCo 预训练打底、共享坐标系把两图绑在一起、解码器层间留了交换信息的路。
  • 置信度不需要额外监督（C* ≈ α/ℓ），训练中自然收敛，并立刻在下游派上用场：图对过滤、全局对齐加权都靠它。
  • 预训练和分辨率都是硬贡献：去掉 CroCo 或降回 224，单目深度、多视图深度、视觉定位三个任务一致变差（§4.3 消融）。

5.2局限（论文自述 + 读代码看出来的）

  • 尺度不定：训练时按 avg_dis 归一，网络只对形状负责；绝对尺度要靠已知的位姿、深度范围或物体尺寸做对齐（多视图深度的绝对尺度协议里体现得最清楚）。
  • 两两前馈是 O(N²)：大场景必须靠检索裁边，且每对独立预测，跨对一致性完全依赖后端全局对齐兜底，而不是网络内生。
  • 静态世界假设：动态物体在两张点图里坐标对不上，只能靠低置信度掩掉；论文没有处理动态场景的机制。
  • 显存与分辨率耦合：512² 的逐像素点图加置信度，再往上提分辨率开销平方级增长；单目疑难场景（KITTI 远处）精度仍不及同域训练的专用网络。

5.3后续方向

  • 论文自己指的路：更大模型、更多数据、更多任务头，以及把点图范式推广到更广的几何视觉任务。
  • 同团队的实际后续：MASt3R（加显式局部特征头与 InfoNCE 匹配损失，把隐式对应磨锐，匹配类任务再涨一截）、Spann3R（流式递增重建，摆脱两两前馈）、MonST3R（动态场景的点图）。
  • 社区沿这条路长出来的：Fast3R（多图一次前馈）、VGGT（2025，前馈大模型一次输出全部相机参数与点图）——点图回归已经从一篇文章长成一条路线。
  • 和本站其他路线的对照也值得一看：渲染式预训练用「画得像不像」当监督，点图回归用「坐标对不对」当监督——一个从外观侧、一个从几何侧逼网络理解 3D，互为镜像。
